### 5. 证据外仓：原则批准 ——「Git 中的可信索引 + 外部不可变原件」
- Git 保留权威索引：RUN Record、判定结果、源码与 Host SHA、manifest、每份证据的 SHA-256/大小/存储位置/保留策略；须足以判断结果、验证来源、定位原始证据。
- 外部存储：不可变原件（完整 Host 日志、transcript、超大收据、复验原始数据）；内容寻址或版本化对象存储，禁止静默覆盖。
- 原则：全新检出可凭 manifest 取回并逐文件哈希校验；上传成功≠迁移完成，必须抽样下载-复验-恢复，原件经验证后方可按保留策略处理；短期 CI Artifact 不得作为唯一长期证据仓库；私有日志/含令牌数据需访问控制与敏感内容检查；**不通过大规模改写 Git 历史瘦身**。
- 节奏：规则先适用于新 RUN，再迁移存量；后端选型（MinIO/S3 兼容等）由 Agent 按可部署性与恢复能力决定，非科研架构决策。

### 6. 主检出 reset：**有条件批准**
- 允许自主完成受控序列：核实备份分支在远端且 SHA 符合预期 → 盘点主检出未提交修改/未跟踪与忽略文件/唯一提交/活动进程 → 确认无需要保留的独有证据 → 恢复到已验证的 origin/master。
- **优先 fast-forward**；必须硬重置时，仅对已明确盘点为可丢弃的主检出执行，记录前后 HEAD、工作区状态与恢复入口。
- **不授权**：`git clean -fdx`、批量删除 worktree、强制改写备份分支、存在活动 World 时直接清理。
