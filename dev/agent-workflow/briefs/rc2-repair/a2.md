## 1. Confirmed root cause (do not re-diagnose; verify while reading)

The setup-time persona overlay still resolves personas from the ROW-LEVEL
blueprint (`config.blueprintSource`, parsed once per boot root), not from the
TeamSession's bound blueprint snapshot — the live authority for everything else
(catalog, compatibility, capability placement). When the row's anchor document
and the bound snapshot diverge (e.g. the row config carries a blueprint without
the member template the team actually bound), a fresh member's durable create
succeeds, the post-commit binder fails to locate the template in the persona
source, and the create reports a FALSE `rejected`.

## 2. Required semantics (plan §5.2/§5.3)

- The persona source must resolve personas from the bound blueprint snapshot of
  the TARGET team root — the same authority the capability path uses.
- Recommended (plan-conform) implementation:
  - add an OPTIONAL param `resolveBoundBlueprint?: (teamRootSid: string) => TeamBlueprint`
    to `TeamProductionRootParams` in `root.ts`;
  - `host.ts` passes its EXISTING `resolveBoundBlueprint` (≈ L1188) into
    `createTeamProductionRoot` (single source of truth — do not duplicate the
    resolution logic in root.ts);
  - in `root.ts`, build `personaSource` so that `getLeaderPersona(root)` /
    `getMemberPersona(root, templateId)` resolve the blueprint for `root` via
    the injected resolver (cache per root in a Map — the resolver is not
    expected to be called repeatedly per persona step), then read the template
    from THAT document. Template-not-found keeps the existing typed throw.
  - **Factory world (resolver absent)**: behavior is UNCHANGED (the row-anchor
    closure, exactly as today) — the harness/boot worlds must keep working.
  - **Production (resolver injected)**: NEVER fall back to `config.blueprintSource`
    for persona — a resolver failure propagates (fail closed, the setup
    rejection rolls the unpublished agent back). The legacy row-without-ref case
    is handled inside the host resolver itself (row anchor) — consistent with
    the capability path; that is not a silent plugin-side fallback.
- `agent-bindings.mjs` `installPersonaForSetup`: the row-config skip
  (`config.blueprintSource === '' → return`) must apply ONLY when no
  `resolveBoundBlueprint` was injected (factory world). When the resolver is
  injected (production), proceed to `slot.apply` — a root without a durable
  TeamSession row then fails closed through the resolver's throw (loud, typed),
  never silently persona-less. Keep the existing comment block accurate.
- Do NOT change the capability path (`getBoundBlueprint`), the catalog wiring,
  the compatibility prober/authority, or the T12-M2 blueprint re-parse at
  ≈ L1033–1047.
