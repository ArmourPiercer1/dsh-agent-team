## 1. Confirmed root cause (do not re-diagnose; verify while reading)

`packages/runtime/control/service.ts` → `guardOperation()` (≈ L1241–1252):

```ts
const member = repositories.memberInstances.get(root, target)
if (
  repositories.teamSessions.get(root) === undefined ||
  member === undefined ||
  !GUARD_LIVE_LIFECYCLES.includes(String(member.lifecycle))
) {
  return { allowed: false, reason: CONTROL_GUARD_BLOCK_REASONS.TARGET_STALE }
}
```

The leader is a schema-v2 special record (contracts `validateLeaderInstanceRecord`,
`packages/contracts/src/dto/member-instance-record.ts` ≈ L301): it carries **no
`lifecycle`** and no `childSessionId` (invariant 15; a lifecycle key is contract-rejected).
So for `target = LEADER_INSTANCE_ID`, `String(member.lifecycle) === 'undefined'` and the
leader is always `target-stale` — its ask→approve operations can never pass the
last-mile guard. Ordinary members keep the current three-part check.
