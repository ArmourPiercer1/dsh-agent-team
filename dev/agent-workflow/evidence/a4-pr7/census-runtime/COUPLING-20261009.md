## 3. when the leg reads it — measured, not assumed

The leg's order was: spawn the real gate (`spawnSync`), and **after it exits** read the build state
for its disclosure/branching (`artifactProvenance` → `treeShape`). So there are two reads of the same
mutable path, separated by the whole gate run.

When does the gate read the entry inside its own process? Sweep: run the real gate, hold the entry
away from offset X, print what the client arm said (`find-gate-read-offset.sh`):

```

hold_at=+0.85s  client arm said: PASS client plugin (packages/client): name="dsh-agent-team-c
```

The gate's own read is at **+0.40 s ± 0.05 s**; the gate process ends at **+0.80 s** (`/usr/bin/time`:
`gate run 0.80 s`, `gate run 0.81 s`); the leg reads the tree immediately after, and the leg's whole
duration is 0.89–1.04 s. So the leg contradicts itself if a hold opens anywhere in roughly
**+0.40 s … +1.1 s** — and a real hold, measured above, lasts **2.4–3.2 s**, i.e. longer than the
entire leg.

The plant is not an invented state: it performs the same `mv … → ….held-by-7-6-gate` the sibling file
performs, and only chooses the offset the census chooses by scheduling
(`plant-sweep.sh`, single leg: `vitest run <file> -t 'never reports a passing gate over a step it did not run'`).

## 5. the fix

`packages/testkit/test/a4p75-composition-smoke-classification.test.ts`, the live leg only (+92 / −34).
The leg no longer decides **which** contract to assert from a live read of build state. It now asserts
one contract, from the report the gate itself printed:

1. **agreement** — whatever the report contains, an unverified step (a `SKIP`, a `FAIL` line, a wrong
   footer) may not exit 0 and may not print `PASS composition-smoke`; a report with nothing unverified
   in it must exit 0 and must print the unqualified footer. This is exactly what the three old
   branches spelled out, now stated once and valid in every tree state.
2. **anti-vacuity** — `run.steps` must carry `PLUGIN_TARGETS.length + REQUIRED_CHECK_IDS.length` lines
   and each derived arm label exactly once, so a report that goes quiet cannot satisfy clause 1.
   Derived from the same imports the gate uses; no literal count.
3. **report integrity per shape**, keyed on the gate's own line for the closure-gated arm rather than
   on a second read of the tree: if that line says `built entry is missing` the run must name
   `pnpm build`, must report no skips, and must footer-FAIL; if it starts `SKIP ` the footer must name
   the arm and say `NOT RUN and NOT passed`.

The tree state is still disclosed — sampled **before and after** the gate run, printed in every
assertion message, with an explicit
`|| THE TREE MOVED UNDER THIS LEG between the two samples; neither sample is a premise of any assertion below`
when the two samples differ. It is diagnostics, not a premise.

**What is not weakened.** The per-shape wordings stay pinned where the pinning leg controls the state
itself: the four fixture cases (`green` / `skipped` / `failed` / `absent`) build their own repositories,
and `a4p7-merge-gate.test.ts` owns the three real-tree mutations (never-built :1049, partial output
:1083, untraversable closure :1137), each asserting the shape it created. "The artifact this
repository ships must actually load and be green" stays pinned by that file's healthy composition leg
at :837 ("is green, asserted by arm name and by absence of a skip — never by the exit code"), which
admits only `passed` and demands the unqualified footer at :894. What
this leg owns is the sentence in its title, and it now asserts exactly that from one observation.
No fixture expectation was edited; the tolerance set, the capture count, and the refuse semantics were
not touched — the published baseline stays the 9 named reds
(`dev/agent-workflow/evidence/a4-pr7/population-baseline/nine-root-post-d3-4-split.ids.txt`, 9 lines),
and this identity is not in it (`baselineIds`, 9 entries, none of them this file).

## 7. rejected fix options (and the measurement behind each rejection)

- **A knob on the gate** (`--expect-built`, an env var, a fixture pointer): the gate family is
  deliberately knobless and a leg in this very file pins it — `composition-smoke{,-bundle,-targets}.mjs`
  must contain no `process.env`, `globalThis`, or `process.argv` (test at :1487). Adding a knob means
  unpinning the property that there is no mute seam.
- **A declarative build-artifact snapshot taken before the census**: `artifactProvenance` throws unless
  its root is a git toplevel, so a snapshot root cannot be measured by the same instrument; and the
  snapshot is incomplete anyway — the third hold moves `node_modules/.pnpm/node_modules/clsx`, a
  hoisted dependency outside any dist, so a dist-only snapshot still leaves a mutable input to the
  same gate. A hardlink farm of `node_modules` is not a 126-line test fix.
- **`--fileParallelism=false` for the census**: it would serialize 508 files to dodge one coupling,
  leave the race intact for `pnpm test`, and make the census slower than the runner's budget.
- **Tolerance / capture-count / refuse edits**: not done and not defensible — the identity is a real
  defect of this leg (a red that is not a function of the tree), and rule 3 of the plan's
  §7.6 census section is "fix the leg or the build, never to accept the red".

## 9. NOT ESTABLISHED

1. **Which of the three holds straddled on the hosted runner.** The artifact excerpt quotes the leg's
   disclosure line but not the failing assertion. The disclosure's shape — entry absent, output root
   present and carrying 400 files — is the signature of the `:1083` entry-only hold (the `:1049`
   whole-root hold removes the root too, and the watcher confirms that variant reports the root absent),
   but the runner's log does not carry an `mv` attribution, so this is an inference from a message
   signature, not a measurement of that run.
2. **Why the hosted runner lands the overlap and this 32-core box did not in four captures.** The
   measured local schedule keeps the leg ~13 s behind the holds (§6); the hosted durations are from a
   2-core runner. The overlap is reproduced deterministically by the plant, never by local scheduling.
3. **Whether any other census identity reads a path a sibling mutates.** I grepped the mutation
   surface of the `.held-by-7-6-gate` family and read the two files that reference it; that is not an
   audit of all 508 files. The hygiene lane's precedent suggests other consumers were already taught
   this lesson, which is consistent with this being the only identity that moved.
4. **Whether the merge-gate holds themselves are safe under the same concurrency.** They mutate state
   they own and read it inside the same worker, so the specific read/premise coupling does not exist
   there; I did not attempt to break them, and `a4p7-merge-gate.test.ts` is outside this lane's
   ownership (frozen).
5. **A census-level "before" reproduction on this machine.** Not achieved; stated as such in §6 rather
   than substituted by the plant.
