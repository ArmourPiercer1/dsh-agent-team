## DISCLOSURE: one site the fence used to see is now invisible TO THE FENCE.

Of the 34 base-only sites, 33 are promotions (the document genuinely declares v3 now, and the
fence correctly stops flagging a v3 document). The 34th is `L323=v4`, the
NEG_SCHEMA_VERSION_MISMATCH witness. It was a YAML literal `schemaVersion: 4`; it is now
`schemaVersion: ${SCHEMA_VERSION_NEVER_DEFINED}` with `const SCHEMA_VERSION_NEVER_DEFINED = 4`.
The fence's digit pattern does not match an interpolation, so this path no longer appears in its
dirty set — the emitted BYTES are unchanged (multiset census: `LOST {'schemaVersion: 4': 1}`,
`GAINED {'schemaVersion: ${SCHEMA_VERSION_NEVER_DEFINED}': 1}`, byte-identical output).

That is a real reduction in what the TEXT SCAN can see, so the witness had to move somewhere with
teeth, and it moved into the type system: at the §7.3 flip `TeamBlueprint['schemaVersion']` narrows
to `3`, and `SCHEMA_VERSION_NEVER_DEFINED = 4` becomes a compile error at the use site naming this
file — which is the whole point of the carrier idiom and why it was preferred over deleting the
digit or re-pointing the expectation. House precedent, same shape, already on master:
`NEVER_DEFINED_VERSION = 99` in `bp1-blueprint-inspector.test.ts:45`. So: fewer dirty sites, no
weaker claim, and the guard is now one the compiler enforces instead of a grep.
