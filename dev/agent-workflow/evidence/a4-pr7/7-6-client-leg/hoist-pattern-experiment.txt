Node walks the ancestor chain of the realpath, and every package under .pnpm/ has
node_modules/.pnpm/node_modules/ in that chain, so an import the upstream package never
declared is answered by the hoist directory — pnpm's default hoist-pattern ['*'].
packages/client/node_modules/clsx exists but is not on that chain; experiment 1 and 2 above
are exactly that distinction.

# Is declaring hoistPattern: ['*'] lockfile-neutral? (the discriminating test)

Two pristine `git archive HEAD` exports, identical except for the declaration, each with
node_modules AND pnpm-lock.yaml absent so pnpm must really re-resolve:
$ rm -f pnpm-lock.yaml && pnpm install --lockfile-only --offline --store-dir=$STORE --ignore-scripts --no-frozen-lockfile
  without declaration -> lock A      with declaration -> lock B
$ cmp A B  ->  byte-identical   => LOCKFILE-NEUTRAL
  settings block, either side:  autoInstallPeers: true / excludeLinksFromLockfile: false
  (hoistPattern is not recorded in the lockfile's settings at all, which is why the
   override-order fix in byte-canonical-lock.txt was load-bearing and this is not)

# POSITIVE CONTROL: pnpm really reads the key (it is not silently ignored)

Pristine export, full offline frozen install with hoistPattern: ['@types/*']:
  clsx in .pnpm/node_modules:      NO  — the narrowed pattern took effect
