## 4. Generation/nonce discipline — no breaker double-pass window (TRACED, no REQUEST-CHANGES trigger)
All destructive breaker effects are `unlink(aside)` (unique per-breaker name) or reclaim `link(aside→path)`; the only unlink-by-name is release, which is inode-pinned.
- **Judged branch** (`:692-706`): unlink requires `inode(aside)==judgedInode` (rename preserves inode; `judgedInode` lstat'd AFTER revalidation `:677-680`) **AND** `moved.nonce===holder.nonce`. A live generation can never carry the judged nonce (per-acquire `randomUUID`; only the judged record's bytes carry it), so even ext4 **inode-number reuse** cannot pass the AND — a reused-inode file matches inode but not nonce → falls into the reclaim branch. Beat rotates `token` but not `nonce`/`pid`/`boot`/`host`, so the death proof covers the whole generation, exactly as the comment claims.
- **Two breakers both passing verify-after** is possible only against the SAME *dead* generation (e.g. reclaim puts the judged inode back at the name and a second breaker legitimately re-judges it): both then destroy only bytes with a standing death proof — idempotent, not the bug class. I could not construct a window where the second passer destroys live bytes.
- **Reclaim-lost branch** (`:722-735`): unlinks aside only if bytes are the judged dead generation, or `superseded` = name shows same-nonce/**different-token** = owner demonstrably re-published (breakers' own link-restore preserves the token, so the predicate cannot be self-forged); else **retained as aside** — never-steal honored.
- **Holder side**: creator read-back (`:618`), beat double-check (pre-temp `:635`, pre-rename `:639`; foreign → stop-forever, free → `link` create-if-absent `:640`), release `lost` short-circuit (`:653`) + dev:ino pin around the nonce check with re-pin (`:658-664`). A live holder can never be *judged* breakable (pidAlive → `mayBreak` false), so the pinned release unlink targets only its own generation.
