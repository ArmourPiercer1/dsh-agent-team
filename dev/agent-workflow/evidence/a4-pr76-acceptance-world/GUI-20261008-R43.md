## Three instrument slips of mine, caught by cross-checking (the point of doing this in the open)

1. **`node boot.mjs --detach` inside a normal tool call dies with that call**: the supervisor, mock and
   host are spawned into that call's private PID namespace, so the port answered `401` for seconds and
   then `ERR_CONNECTION_REFUSED` (this is what killed the browser's first navigate). The world must be
   held by a managed background job — which is how the leg was finally run. Round 34's F3 note about
   the marker recording the wrong PIDs is the same fault seen from the other side.
2. **My teardown assertion was the weak instrument**: `P=$(curl -w '%{http_code}' … || echo 000)` makes
   curl print `000` *and* fire the fallback, so `$P` became `000000` and my verdict line printed
   `PORT STILL ANSWERS` for a host that was already gone. The real check is a socket connect
   (`connect_ex(3180) = 111` → refused). The F3 rule stands and is now sharper: assert on the **port**,
   and never build that assertion out of a command that both reports and fails.
3. **`pgrep -fa "dsh.*3180" | wc -l` returned 3** for a host with no listener: two of the hits were my
   own sandbox wrapper and my own command line, which contains the pattern. A process count that
   matches the observer is not a process count.
