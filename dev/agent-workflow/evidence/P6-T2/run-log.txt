[2026-08-29] STEP 5 — implementation (STARTED)
Design (documented in module headers; enforcement order is the facade contract):
  (1) team + target resolution — instanceId-first (rootSessionId, instanceId);
      label/template tokens are REJECTED (ACTION_ADDRESSING_REJECTED);
  (2) caller identity+role from TeamDomain (human / leader / member;
      DISPOSED or ARCHIVED caller = stale -> CALLER_ROLE_STALE);
  (3) caller authority + mutation envelope — human: NOT team-envelope-bound
      (inv 34; external hard policy is per-capability, enforced by the policy
      resolver, no op-level external hard deny exists in v1 contracts);
      leader: team envelope (blueprint.teamEnvelope ∖ deny; leader template
      entry intersected when present); member: team ∩ template ∩ instance
      autonomy-overlay envelope (P6-T2 convention: overlay values may carry
      an `envelope` {allow,deny} key in the free-form storage `values`);
      fail-closed: op absent from any allow set = out-of-bounds.
  (4) compatibility/admission — work actions gated by the durable compat
      state (absent -> live evaluation via the reused domain/compatibility
      bridge); target must be in WORK_ACCEPTING_STATES for work actions;
  (5) quota — creation actions enforce INSIDE ActivationProvider step 7 under
      its per-team lock on a fresh durable view (in-flight PREPARED counted);
      boundary: admitted iff count+1 <= limit (at-exact-limit rejects);
      non-creation actions consume no creation budget; provider QUOTA_* codes
      mapped to router codes;
  (6) effects — durable writes ONLY via the injected TeamDomain repositories
      (inv 41) under the router's per-team lock; state change first, evidence
      fact second (documented bounded non-atomicity on mid-effect fault).
Modules: runtime/admission/{errors,types,actions,resolve,envelope,gate,index}.ts
         runtime/action-router/{effects,router,index}.ts

[2026-08-29] STEP 5 (cont.) — design rulings + results (DONE)
- Durable-write boundary (frozen-plan ruling): packages/runtime/lifecycle* is
  owned by P7-T3. The facade NEVER rewrites member records (append-only store:
  identical bytes -> no-op; different bytes same key -> RECORD_DUPLICATE).
  Lifecycle transitions commit through the injected LifecycleCommitPort;
  absent port -> LIFECYCLE_COMMIT_UNAVAILABLE (fail-closed, zero durable
  effects). Work admission with a non-RUNNING target still commits the
  work-admitted fact with lifecycleCommitted=false and fromLifecycle set.
- Facade's own durable writes = ledger facts only (team-work-admitted,
  member-lifecycle-changed, team-coordination-recorded) via commitFact
  (allocateSequence -> entry put) under the router per-team lock; state change
  first, evidence fact second (documented bounded non-atomicity on mid-effect
  fault: DURABLE_WRITE_FAILED).
- Remote-safe payloads: optionalStringField conditional spread — never store
  undefined (the remote seam rejects undefined values as RECORD_INVALID).
- Ledger sequence numbers always via ledger.allocateSequence().
- Quota semantics (documented boundary): count+1 > limit -> reject;
  count+1 == limit -> in-boundary (allowed). Check order: team, then template.
  Enforced SOLELY inside ActivationProvider step-7 admission (single source
  of truth; the router keeps no counters).
- C2/C3 redesign rationale: a delegation carrying templateId for a NON-fresh
  template that has an active instance resolves to 'continue' (work-admitted,
  no creation) under provider delegation mapping M1-M5. The P6T2 blueprint's
  only fresh_per_delegation template is 'scout', so the template-quota
  boundary is exercised with scout: C2 isolates it (team stays in-boundary
  3+1=4<=4 -> QUOTA_EXCEEDED_TEMPLATE_INSTANCES, zero writes); C3 fires 4
  parallel scout delegations -> exactly 1 member-activated, 3
  QUOTA_EXCEEDED_TEMPLATE_INSTANCES, scoutCount=2, teamTotal=3.
- Closed role sets per action spec (DELEGATE=[leader], CREATE_MEMBER=[human,
  leader], ...): member self-escalation is rejected CALLER_AUTHORITY_DENIED;
  delegate requires assign-task AND create-member (may-create, fail-closed).
- Envelope: an op is in-bounds only when EVERY applicable allow-set allows it
  and no deny-set denies it; absent from an allow-set = out-of-bounds (fail
  closed). member = team ∩ template ∩ newest-generation instance overlay
  (values['envelope']); leader = teamEnvelope minus deny, intersected with the
  leader-template entry; human = ALL_MUTATION_OPS (inv 34: humans are not
  team-envelope-bound).
- Compat gate (inv 50) blocks NEW work admission only; coordination and
  lifecycle ops are exempt.
- Test-infra discoveries (measured): the vitest shim supports ONLY
  toBe/toEqual/toBeGreaterThan/toThrow (+ .not forms); toContain/
  toBeDefined/toHaveLength throw TypeError. Seam writeCount / childFactory /
  memberList / portCall deltas must be captured IMMEDIATELY after each action
  (a delta computed at the end of a setup block is contaminated by the later
  actions' writes).
