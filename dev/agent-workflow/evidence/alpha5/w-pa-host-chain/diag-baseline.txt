  once (`ambiguous-family:` as the prefix, the count appended at runtime).

  Honest shadowing note (kept ORIGINAL evaluation order, so not a defect to "fix" here): on the
  call-level path `bindingFamilyOf` runs BEFORE `matchUniqueBindingEntry`, so a missing mount surface
  reports `no-seed-entry` (that is what the earlier line sees) and `no-surface` / `surface-no-entry-of`
  / `no-binding-family` fire only when a family exists and the surface breaks afterwards. The
  distinguishable set on a live call is therefore: no-mount, mount-instance-mismatch,
  no-placement-name, no-seed-entry, seed-no-binding-id, no-entry-for-placement, entry-not-verified,
  binding-not-active, ambiguous-family:<n>, bad-binding-revision, bad-definition-identity.

  Real codes captured from the production entry (values from the fixture mount in

`a5p1-guard: <event> agent=<session>…`. The old formatter printed only `tool` and `denied` and dropped
the rest of the payload. It is now a PASS-THROUGH over a fixed allowlist (`GUARD_OBSERVATION_FIELDS`,

  published, residue, mask, maskLiftable, hostDisposeReturned, note
