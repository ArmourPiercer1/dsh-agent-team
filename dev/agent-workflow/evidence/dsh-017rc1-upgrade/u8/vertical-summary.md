## (c) 0.1.7 behavior observations

### (c.1) Deltas found by the U8 vertical itself (run-1/run-2 blockers + run-3 adaptations)

1. **Profile-plugin compatibility preflight rejects nameless rows** (run-1 V0 blocker; genuine 0.1.7 bug in the new feature): 0.1.7's `packages/boot/app-boot/src/compatibility-preflight.ts` runs `manifestOf(ctx, row.name, base)` for every composed row, and `manifestOf` crashes on `row.name === undefined` (`name.startsWith('cordis:')`) → the row is disabled with the misleading denial `its declared peer dependencies cannot be validated: Cannot read properties of undefined (reading 'startsWith')`. Config-only override rows (`{id, config}` without `name`) — the pattern implied by the bundle-patch header — are therefore silently killed. The rc2 kit pattern (override rows carry the same `name` as the bundle row) works: preflight resolves the package manifest (no `peerDependencies` → compatible) and the named override wins at runtime. Evidence: run 1's boot log is quoted in `vertical.log` (V0 section, the preflight crash + the misleading denial line); the working named-row boot is in every subsequent run's `v0-boot/instance-1.log` (run-11's in place). Worlds `u8-017rc1-2026-09-24T13-13-03` (run-1) and `u8-017rc1-2026-09-24T13-33-14` (run-3) retained. Follow-up: upstream should guard `row.name === undefined` in `manifestOf` (or document that profile-patch override rows must carry `name`).
2. **Remote session API: no auto-create; prompt resolves on accept**: `session/prompt` for an unknown sessionId now returns `{ok:false, code:'session/not-found'}` (verified: 0.1.5 auto-created); sessions must be created explicitly via `/api/session/create` (`{sessionId?, cwd?, workspaceId?, agentPreset?}` → `{ok:true, value:{sessionId, agentPreset}}`). `session/prompt` (mode `queue`) resolves immediately with `{ok:true, value:{accepted:true}}` — the turn runs asynchronously server-side (turn completion observable via the model wire / session log, not via prompt settlement). Endpoint routing is per-method: `POST /api/session/<method>` (posting `session/create` to `/api/session/prompt` → `gateway/bad-request`).
3. **LLM wire protocol: OpenAI chat-completions → DeepSeek Messages API**: 0.1.7's `dsh-llm-deepseek` adapter (`src/adapter.ts`, `src/messages-api.ts`, `src/serialize.ts`, `src/translate.ts`) POSTs to `<DEEPSEEK_BASE_URL>/v1/messages` with an Anthropic-style body (`messages[].content` = block arrays; tool calls = assistant `tool_use` blocks; tool results = USER messages carrying `tool_result` blocks; `tools: [{name, description, input_schema}]`) and expects an SSE stream of `message_start` / `content_block_start|delta|stop` / `message_delta`(stop_reason) / `message_stop` (validated in `translate.ts`: `message_stop` requires all blocks closed + a settled stop reason; tool-call final input must parse to a JSON object). The 0.1.5-era mock (`/chat/completions`) 404s every 0.1.7 model call — silently, until the turn stalls. Adapted on the task-kit side only: `packages/tools/harness/mock-deepseek.mjs` now serves BOTH routes (protocol chosen by path; the injected `decide` contract is unchanged), and the vertical's transcript helpers are dual-protocol (OpenAI string/tool-role shape and Messages block shape). End-to-end proof: scratch host + adapted mock — full turn lifecycle persisted in the V4 log (`user/message` → `request/header` → `assistant/message` "E2E_PONG_FINAL" → `turn/end` completed), incl. the title side-call (0.1.7 wording: "Generate the session title from this…" — no tools in the request, which is also the robust side-call guard). Scratch worlds: `u8-e2e3-*` / `u8-e2e4-*` under the round scratch dir (deleted at round close; the full-turn V4 evidence is captured in the retained worlds above).

Plugin-side robustness follow-up: make the builtin-deny restrict wrapper tolerate non-restrictable names (see (e)).
10. **The `bash` tool now REQUIRES a `description` argument** (run-6 V4/V6): 0.1.7's bash tool schema added a required `description` property (matching the harness's own bash tool — "Clear, concise description of what this command does"). A call carrying only `{command}` fails argument validation with `Error: invalid arguments: missing required property "description"` — AFTER the permission lane (an `ask`-lane bash with a missing description still creates the durable control request; approving it just runs the invalid call). Kit-side adaptation: every scripted bash call carries a `description`. Any 0.1.5-era automation/scripting that emits bare `{command}` bash calls breaks silently-ish (the error is a normal tool result, so a model may retry or give up — a mock/script must carry the field).
11. **`requestToken` is the work-unit idempotency key — replaying a settled token = `WORK_REPLAYED`, member NOT re-spawned** (run-6 V6b): 0.1.7's `team_delegate` work ledger keys work units by `requestToken`. The p6t6 path (1) is kept first (harmless; works if a future host change surfaces them). Follow-up: the harness UI/state cannot display pending approvals of created teams today — consider a per-team control query or surfacing created-team requests in the directive state (see (e)).
