# 测试实例基础设施 — 搭建与权限模式实测（2026-08-29）

## 结论（对用户"workspace-write 下能否免批准完成测试"的回答）

**能。** 除前端 bundle 构建外（见 §5，非 G1 判据），测试实例的 install / build / launch / 验证全部在 workspace-write 沙箱内完成，零升级请求。

## 1. 权限模式实测（workspace-write，无升级）

| 探测 | 结果 |
|---|---|
| 写 `references/.dsh-test`（工作区内 DSH_HOME） | **OK** |
| 写 `C:\Users\user\.dsh-dev`（工作区外） | 拒绝 `UnauthorizedAccessException`（该路径已弃用，见 TEST_METHODS §6 第三次裁决） |
| pwsh→git / pwsh→node 一层 spawn | OK（沙箱只限解释器嵌套 spawn） |
| node→任意 piped-stdio 子进程（node→node、node→git、esbuild service） | **EPERM -4048**（同步/异步/worker-threads 模式全部实测失败；esbuild 0.25.12 async 路径硬编码 `stdio:["pipe","pipe","inherit"]` 子进程 spawn，无 worker 旁路） |
| `stdio: 'inherit'` 的 spawn（`scripts/build.ts` runScript→pnpm） | OK |
| 升级请求（`sandbox_permissions: danger-full-access` 探针，用户授权测试"替我审批"） | 请求仍到达用户，被拒 → **"替我审批"不生效；此后不再发起升级请求** |

## 2. 可用绕行链（已写入 TEST_METHODS §2）

```
pnpm install --ignore-scripts          # lifecycle spawn EPERM；预编译原生包不受影响（P1-T1 同款结论）
node scripts/build.ts                   # node v24.20.0 原生 type-stripping，绕开 tsx（tsx=esbuild 同步 API=必 EPERM）
  env DSH_CLIENT_COMMIT_HASH=cd5ef814   # 跳过 build 内 node→git spawn（execFileSync rev-parse HEAD）
  env ESBUILD_WORKER_THREADS=1          # 保留（对 vite 无效，但对潜在 async-esbuild 消费者无害）
node apps/cli/lib/bin.js web --port 3180 --no-open   # 构建产物入口，绕开 tsx
  env DSH_HOME=<workspace>/references/.dsh-test      # 工作区内 → workspace-write 可写
```

## 4. 验证输出

- `GET http://127.0.0.1:3180`（无 token）→ **401**（0.1.2-alpha.1 的启动 token 鉴权门生效；稳定实例 0.1.1-rc.2 无此门，故 :3080 裸 GET 200）
- `GET http://127.0.0.1:3180/?token=<launch-token>` → **404**（前端 bundle `apps/web/dist` 缺失；server 本身健康）
- `GET http://127.0.0.1:3080` → 200（稳定实例未受影响，全程未触碰）
- 启动 URL 行即 host boot 完成信号（plugin tree loaded 后才打印）；boot 无错误行。

## 5. 唯一沙箱内不可行项：前端 bundle

`apps/web/dist` 无法在沙箱内构建（vite build 的 config 打包 + TS 转换均走 esbuild service spawn）。影响面：浏览器页面 404。**G1 判据（DevPlan §13.6 冻结文本）不含浏览器 GUI**——需要的是 "plugin can be composed with pristine upstream"（host 侧 composition，经 `DSH_HOME/profiles/web` 的 `dsh.profile.bundles` / `cordis.patch.yml` 公开 seam）与 "pristine upstream remains byte/source clean after test"。若后续 Phase 需要渲染 GUI：用户在工作区外手动跑一次 `pnpm build:web`（一次性，非每轮），产物为 gitignored 构建输出，不违反 pristine 角色。

## 6. Public seam 记录（G1 smoke 挂载路径）

`references/.dsh-test/profiles/web/`：
- `package.json` → `dsh.profile.bundles: ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app"]`，`nodeLinker: hoisted`
- `cordis.patch.yml` → 初始 `[]`（bundle 之后的顶层 patch 数组；支持 `!!js`）
- 组合序：bundles → cordis.patch.yml → `--patch` overlay
- 挂载外部插件 = 在该 profile 目录加 dependency + bundle 条目（或 patch 数组插入），全部位于工作区内 DSH_HOME，不触 test-use 源码。
