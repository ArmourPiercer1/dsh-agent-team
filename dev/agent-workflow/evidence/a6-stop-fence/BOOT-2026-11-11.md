# Main-agent boot of PR #710 (owner ruling A fence)

Dated 2026-11-11. Append-only note; the lane's `README.md` above is untouched.

## Why this note exists

The fence in this PR changes *when* a durable `control-allow-consumed` fact may be
written. Host-free tests can prove the guard's branch logic and the abandonment
fact, but only a real Host boot can show the race the owner ruled on: a human
`allow` decided, then `session/cancel` (Stop) arriving before the consumption
write. `A6-12` is that arm.

Both boots below were run by the **main agent** (repo rule: a PR is not
submittable on a subagent's boot).

## Instrument finding, recorded because it cost real time

The kit needs `C1_PLANE_TAKEOVER=1` on the A6 officer path. Without it the base
YAML emitter indents the worker `deny` block's `resource:` at 10 columns instead
of 12 (`tests/kits/c1-leader-approval-smoke/c1-leader-approval-smoke.mjs:750`,
the `PLANE_TAKEOVER=false` branch), the saved-source index rejects all four
blueprints as `yaml-invalid`, and the first symptom is a misleading
`MALFORMED_DTO blueprint not found in catalog: team.c1-a6-officer`. It is not a
product failure and not the fence. The independent adjudicator reproduced this
on the unmodified candidate tree and recorded both logs (report §12,
`instrument-2026-11-11/`); the two-character fix is **reported, not applied**
(tracked test infrastructure, its owner's call).

## CORRECTION — 2026-11-11 (review finding on PR #710). Append-only: the sentences above are NOT rewritten.

Two claims above are not supported by any kept artifact. They are corrected
here rather than edited in place.

**(1) The `seq 14 / no seq 15 / seq 16 control-request-abandoned` row is not
captured.** The paragraph under "What this does and does not establish" says
the adjudicator's `--keep` run shows "decision `seq 14`, **no `seq 15`**, then
`seq 16 control-request-abandoned` with reason
`invocation-cancelled-before-consumption`". **No kept artifact contains that
row.** In `../a6-stop-fence-c2/boot-c2pr710-keep/`:

- `a6-stop.json` carries only `cancel` / `lateAllow` / `humanLeg` /
  `lateDecision` / `lateConsumption` (the older kit did not persist the
  abandonment array);
- `a6-human-discovery.json`'s ledger page stops at **seq 13**
  (`control-request-recorded` for `ctrl-04m3c460crhthh1ewb6980qa`, the human
  leg); the allow decision at `seq 14` is present in `a6-stop.json`, but the
  abandonment row was never written into any kept file.

What the kept artifacts DO show: the late allow was refused with
`CONTROL_REQUEST_ABANDONED` (`a6-stop-late-allow.json`), which is the
terminal-mark refusal. The abandonment **sequence 16** and the **reason
`invocation-cancelled-before-consumption`** are therefore **inferred** from the
code path (`service.ts#guardOperation` trip → `commitAbandonmentFact`, which
allocates its own sequence after the burned consumption sequence) plus that
`CONTROL_REQUEST_ABANDONED` refusal. They are **not directly captured** in this
evidence set.

The kit has been fixed in this round to persist `final.abandonments` (and the
human leg's row) into `a6-stop.json`, so the next boot will capture the row
directly; a re-boot by the main agent is required, and this note must be
superseded by that capture rather than read as if it already existed.

**(2) The manifests are instrument-defective: they do not bind the PR head.**
Every `run-manifest.json` under `a6-stop-fence/main-boot-r1|r2` records
`productSha 1964cb71c259475746bf732478eb53e2d197fafc` — the **base/main** tree,
not the booted PR tree — because the kit computed
`git -C process.cwd() rev-parse HEAD` while `--worktree` selected the boot
tree. (The `-c2` runs record `e8ea19c30` for the same reason: that is the
adjudicator's tree, not a stable binding either.) These manifests are
**marked instrument-defective** and must not be cited as binding the PR.

The kit now resolves `git -C <--worktree> rev-parse HEAD` and records
`productTree` alongside `productSha`. Offline check of the corrected
expression, from the main checkout:
`git -C <main> rev-parse HEAD` = `1964cb71c…` (the old, wrong value) while
`git -C .worktrees/stop-fence rev-parse HEAD` = `3d539dc9d…` (the PR head at
the time of writing). No manifest produced by this session binds the PR head —
the main agent's re-boot is the step that produces one.

Nothing else in this note is retracted: both boots still establish that Stop
was admitted after the human allow and that the terminal state carried no
consumption fact and no execution (`A6-11`/`A6-12` PASS, `consumed=false`,
`file=""`). The discriminating evidence for the *trip* (the abandonment row and
the sequence gap) is the host-free `a6-stop-fence.test.ts` arm S9, which is
verified RED against the unwired call site.
