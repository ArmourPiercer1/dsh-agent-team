# Main-agent boot of PR #710 (owner ruling A fence)

Dated 2026-11-11. Append-only note; the lane's `README.md` above is untouched.

## Why this note exists

The fence in this PR changes *when* a durable `control-allow-consumed` fact may be
written. Host-free tests can prove the guard's branch logic and the abandonment
fact, but only a real Host boot can show the race the owner ruled on: a human
`allow` decided, then `session/cancel` (Stop) arriving before the consumption
write. `A6-12` is that arm.

Both boots below were run by the **main agent** (repo rule: a PR is not
submittable on a subagent's boot).

## Instrument finding, recorded because it cost real time

The kit needs `C1_PLANE_TAKEOVER=1` on the A6 officer path. Without it the base
YAML emitter indents the worker `deny` block's `resource:` at 10 columns instead
of 12 (`tests/kits/c1-leader-approval-smoke/c1-leader-approval-smoke.mjs:750`,
the `PLANE_TAKEOVER=false` branch), the saved-source index rejects all four
blueprints as `yaml-invalid`, and the first symptom is a misleading
`MALFORMED_DTO blueprint not found in catalog: team.c1-a6-officer`. It is not a
product failure and not the fence. The independent adjudicator reproduced this
on the unmodified candidate tree and recorded both logs (report §12,
`instrument-2026-11-11/`); the two-character fix is **reported, not applied**
(tracked test infrastructure, its owner's call).

## What this does and does not establish

Establishes, on a real Host: Stop admitted after the human allow, terminal state
reached with **no consumption fact and no execution** on both boots.

Does not establish: that the 4/6 consumption rate measured on the unfenced
candidate is now 0/∞ (two clean boots never do). The discriminating evidence is
structural and is in the adjudicator's `--keep` run under
`../a6-stop-fence-c2/boot-c2pr710-keep/`: decision `seq 14`, **no `seq 15`**,
then `seq 16 control-request-abandoned` with reason
`invocation-cancelled-before-consumption`, and the late allow refused as
`CONTROL_REQUEST_ABANDONED` rather than `CONTROL_REQUEST_DECIDED`. The unfenced
build never wrote that fact — it either consumed or lost the loop.

Not claimed: atomic Stop. The post-check race against the consumption write
remains and is disclosed in `RELEASE-NOTES-0.1.6.md` §8 with its measured
window; the owner's ruling C (per-invocation durable Stop state) is not
implemented.
