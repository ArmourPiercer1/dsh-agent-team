## A1 — Every authoritative write path that settles/advances an approval decision

All durable control facts are appended through one closure-local writer `putEntry` into the TeamDomain ledger (invariant 41: sole durable control authority). Fact families (`service.ts:296–307`):
`control-request-recorded` / `control-decision-recorded` / `control-allow-consumed` / `control-request-abandoned` / `control-escalation-recorded`.

The public surface (`service.ts:5582–5602`) exposes exactly these write entrances; each opens with `withTeamLock(teamLocks, root, …)`:

1. **`requestControl`** (`:2141–2551`) — creates the request row. Appends `control-request-recorded`. Idempotent by scopeKey (legs join the key via `legKeyOf` `:2108–2115`, so leg 2 ≠ leg 1). `leg?: LegFields` (closure-local type `:2082–2098`) — ABSENT = legacy/pre-Alpha.4 row. After the lock releases, at `:2535–2549` it fires `port.notifyLeaderRequest` fire-and-forget **only** when `outcome.created && kind === 'leader-approval'`. Caller-side admission (envelope `request-control`) runs before the lock.
2. **`resolveControl`** (`:2555–~2780`) — the ONE decision writer: the only writer of `control-decision-recorded` for allow/deny. The actual append is closure-local `commitDecision` (`:1992–2072`; payload schemaVersion 2 `{requestId, decision, decider, scope(frozen snapshot incl. authorityScope), requestSequence, reason?, note?, terminalReason?}`). Validates in lock: exists → not abandoned → not decided → role closure → case law → envelope → instance staleness (writes `stale-denied` decision then throws) → external hard-policy probe (writes durable `deny`/`external-policy` then throws) → PA manifest gate (corrupt ⇒ durable deny `authority-undetermined`; valid ⇒ refuse ⇒ durable deny `pa-authority-drift`/`authority-undetermined`) → `commitDecision(allow|deny)`.
3. **`abandonControlRequest`** (`:2879–2967`) — appends `control-request-abandoned` (terminal mark; wins over later decisions) via `commitAbandonmentFact` (`:2802`). Gated by closure-local `mayAbandon` (`:1629`): human/leader may abandon any request; a **member only its own requester rows** — the one existing ownership-scoped authority precedent.
4. **`guardOperation`** (`:3240–3658`) — the last-mile consumption writer: the only writer of `control-allow-consumed` (`:3630–3642`). See A4 for order.
5. **`requestApprovalLeg`** (`:4646–4782`) — opens/returns a case leg. Either delegates to `requestControl` with `leg` fields (ordinal 1), or, when `!hasAuthorityResolver(reviewAuthority)` (`:4699`), calls `closeZeroReviewCaseTransactionally` (`:5288–5417`) which writes a born-terminal pair (leg row + terminal `deny`, `terminalReason:'resolver-unavailable'`) — A1-12.
6. **`escalateApprovalLeg`** (`:4786–5027`) — three writes in ONE lock hold (ADR A5-5): WRITE 1 terminal `deny` reason `escalated` via `commitDecision` (`:4928–4937`, adds `terminalReason:'resolver-unavailable'` when no leg will rise); WRITE 2 `control-escalation-recorded` payload FROZEN at five fields `{approvalCaseId, legOrdinal, previousRequestId, escalatedBy, reason?}` (`:4941–4955`, A3-12(ii) — `note` deliberately excluded); WRITE 3 the risen leg via `writeLegRowLocked` (`:4982`, impl `:4546–4645` — a lock-held writer with no authority of its own, idempotent by legKey). No fourth decision value: `escalate` is a reviewer ACTION (`CONTROL_REVIEW_ACTIONS` types.ts:295–299), never a `CONTROL_DECISION_VALUES` member (A2-1).
7. **`appendTerminalOutcome`** (`:5167–5265`) — the public close of an open leg; appends `control-decision-recorded` whose value comes from `terminalDecisionValueFor` (`:5163–5165`) which **always returns DENY** (A2-8: a close can never mint authority).
8. **`closeApprovalCaseWithoutLeg`** (`:5419–5539`) — closes a case that has no leg (zero-review close): delegates to `closeZeroReviewCaseTransactionally` (`:5288–5417`, named "Transactionally" because `withTeamLock` is non-reentrant — it is the lock OWNER; serialized, not atomic; a retry completes a half-written close, `:5311–5346`).
9. **`commitEffectIfAuthorized`** (`:3979–4024`) — the effect-admission boundary: inside the lock checks abandon/abort and runs the caller's `commitEffect`; writes **no control fact on the authorized path** (the inline-coupling lane continues on the decision and writes no consumption — `:3484–3489`, `:3649–3652`).
10. **`persistAbandonCloseLocked`** (`:4053`, doc `:4026–4052`) — lock-free-by-contract durable close for a caller that ALREADY holds the lock (pre-reservation abort boundary); same `commitAbandonmentFact` primitive, exactly-once.

Read entrances (zero writes): `listControlState`, `readApprovalCaseState` (`:5031`), `listOpenApprovalCases` (`:5055`), `listDecidedApprovalCases` (`:5100`), `findApprovalCaseByIdentity` (`:5541–5581`), `awaitControlDecision` (poll bridge; its abort cascade writes an abandon fact only for INLINE rows, `inlineAbortCascade` `:3697+`).

Production callers of the write entrances (grep-verified): `packages/tools/src/tools.ts:1065` (escalate) / `:1073` (resolve) / `~:1002` (request) — the model-facing team tools, `ctx.caller` derived from the executing agent session (`tools.ts:455–481`, caller-root binding gate `:465–471`, never model input); `packages/runtime/src/plugin/root.ts:~3719` resolveControl remote port (caller HOST-derived, "trusted principal seam stamps the human operator", v4 wire carries no caller/role) and `:~3750` interventionEscalate; `packages/remote/src/handlers/team.ts:812` + `packages/runtime/src/plugin/s6-remote.ts:4125` (`teamResolveControl`); `packages/runtime/action-router/router.ts:576,651` (abandon); `packages/runtime/governance/service.ts:1016–1020` + `governance/permission-approval.ts:408` (mutation lane `requestApprovalLeg`, `reviewAuthority: ask.required`); `packages/runtime/operation-permission/pre-execute-adapter.ts:1905` (v3 case leg) / `:1946–1963` (legacy pre-v3 `requestControl`); `packages/runtime/operation-permission/pa-control-bridge.ts:~400` (`requestControl` for PA asks); `packages/client/src/plugin/team-mount-core.ts:1094`.

There is **no** `resolveApprovalLeg` public method: leg decisions go through `resolveControl` — spec §24.4 "Decision write is one function, two entrances" (`alpha4-permission-governance-spec.md:1072`).

## A2 — How DECIDER identity/authority is computed

**Identity (who the caller is):** `packages/runtime/admission/resolve.ts` `resolveCaller` (`:216–287`), a pure durable read run per call:
- `caller.kind === 'human'` → role `human`;
- `instanceId === LEADER_INSTANCE_ID` (reserved constant) → role `leader` (Leader liveness follows the Root Session; member-row lifecycle never governs the Leader);
- otherwise a live member row must exist (`LIVE_CALLER_LIFECYCLES = ['CREATED','RUNNING','SETTLED']` `:63`; DISPOSED/ARCHIVED → `CALLER_ROLE_STALE`) → role `member`.

The caller is never model-chosen: tool `ctx.caller` is host-derived from the executing session (`tools.ts:455–481`); the remote wire's caller is host-stamped (`root.ts` T12-B4 comment). `checkCallerRoleAuthority` (`:298`) only applies when a spec declares `roles` — the `RESOLVE_CONTROL` action spec (`admission/actions.ts` ~271–277) has `ops: ['resolve-control']` and **no `roles` key**, so members reach the service and die at the service's role closure, not at the facade.

**Authority (who may decide):** `CONTROL_RESOLVER_ROLES` (`types.ts:193–197`):
```ts
export const CONTROL_RESOLVER_ROLES: Record<ControlRequestKind, readonly CallerRole[]> = {
  'leader-approval':  ['leader', 'human'],
  'user-approval':    ['human'],
  'envelope-mutation':['leader', 'human'],
}
```
Doc (`types.ts:178–192`): "A MEMBER is never a resolver for any kind (invariant 37)… role closure is checked before the envelope." The table is keyed **only by the carrier kind** — never by the case, the leg, the subject, or the fingerprint. It is consulted at exactly four points, all identical in shape:
- `service.ts:2622` (resolveControl), `:4852` (escalateApprovalLeg), `:5228` (appendTerminalOutcome), `:5495` (closeApprovalCaseWithoutLeg — "the role table is the ONLY gate", justified by the deny-only asymmetry).
Each: `const allowedRoles = CONTROL_RESOLVER_ROLES[<row>.payload.kind]; if (!allowedRoles.includes(caller.role)) throw CONTROL_RESOLVER_NOT_AUTHORIZED`.

**Decider recorded:** `callerRefOf(caller)` → `ControlCallerRef` (`types.ts:1565–1567`) `{kind:'human',humanId} | {kind:'instance',instanceId, role:'leader'|'member'}`; stored verbatim on the decision row's `decider` field. The durable grammar `parseCallerRef` (`service.ts:518–538`) ACCEPTS `{kind:'instance', role:'member'}` — a member-decider decision row is vocabulary-legal today; only the write-path role closure prevents producing one.

**Per-call vs per-case:** role is resolved PER CALL (fresh durable read, invariant 45); there is NO per-case caller notion and NO global caller cache.

**Critical precision (A6-relevant):** the leg field `reviewAuthority` ("who may decide it", `types.ts:1659–1660`) is **never consulted by the decision write path**. Grep of `reviewAuthority` in `service.ts` shows it used only by: the strict reader (`:852`, `:4424`), `requestApprovalLeg`'s born-terminal check (`:4699`), the escalation successor ladder (`:4905`), the A1-14 consumption recheck (passes `row.reviewAuthority` to the port, `:3210`), and the zero-review close. A leg's *rung adequacy at allow time* is enforced elsewhere: (a) at routing/opening (`approval-routing.ts:338` + carrier table `:200–204`), (b) in the UI/intervention projection (`requiredAuthorityFacts` in `root.ts` pulls `allow` off the offered actions before the operator clicks), (c) the PA verifier at both gates, decider-aware (`:3605–3611` passes `decision.payload.decider`) — **PA rows only**, (d) A1-14 `recheckConsumedAuthority` at consumption — **row-aware, not decider-aware**. Escalation re-entry is closed by case law (`assertNoActOnEarlierLeg`), not by rung. (Consequences beyond this verified chain are (inferred).)

## A3 — ApprovalCase / leg data model

Case = **DERIVED view** over ledger rows (A1-17 — no case row, no case store; `buildApprovalCaseState` `service.ts:4363–4530` strict fold; corrupt row ⇒ `control-corrupt-leg-recorded` mirror + read problem).

- Leg = a `control-request-recorded` row carrying the additive leg fields (types.ts:1643–1673, all quoted in full in the record): `approvalCaseId?`, `legOrdinal?`, `reviewAuthority?: ProposalAuthorityPosition` ("The ladder position this leg was written for — who may decide it"), `requiredAuthorityAtCreation?` ("provenance only; never re-read as authority"), `previousRequestId?` (the ONLY parent pointer), `beneficiaryAuthority?` ("whose authority the case raises (beneficiary, not reviewer)"), `requestedEffect?`, `mutationProposalFingerprint?`. Plus writer-side-only `authorityScope?` (`LegFields.authorityScope` `service.ts:2091–2097`, not projected onto the DTO because the remote v7 wire is frozen).
- **caseId derivation** (A2-7): `caseIdentityKeyOf` (`:4205`) = `[root, kind, subjectIdentity, beneficiary, effect, opFingerprint, mutationFingerprint, authorityScopeKey, correlation].join('\0')`; `approvalCaseIdOf` (`:4230`) = `case-${deterministicToken(key,24)}` — never caller-chosen; `caseIdentityProblemOf` (`:4247`) enforces exactly-one fingerprint (`OPERATION_FINGERPRINT_REQUIRED` A1-15, `AUTHORITY_SCOPE_REQUIRED` A1-14).
- **`ApprovalCaseState`** (`types.ts:548–571`): `{ identity, legs, escalations, currentLeg?, status:'open'|'decided'|'abandoned', terminalDecision?, reviewedBy: ControlCallerRef[] }`. **There is NO assignee/assignment field, NO case version/generation, NO expiry.** `reviewedBy` lists principals who already decided or escalated on some leg. (Alpha.5's separate `tadm:` case binds an `authorityGeneration` into its ID — see A5.)
- **One-shot enforcement, four layers:** (1) per-request first-decision — `CONTROL_REQUEST_DECIDED` at `:2612` (+ abandon terminal at `:2605`); (2) per-case one-act-per-principal — `assertNoActOnEarlierLeg` (`:4153–4198`): scans same-case earlier-ordinal legs for decisions by the same `decider` or escalations by `escalatedBy`; called by ALL THREE case entrances (`resolveControl :2642`, `escalateApprovalLeg :4873`, `appendTerminalOutcome :5242`); (3) per-allow consumption — the guard's `allow-consumed` block + `CONTROL_GUARD_AMBIGUOUS` for >1 unconsumed allow (`:3521–3530`); (4) PA grant ledger validate-then-mark (`tool-admission/grant-mint.ts:111–161`, "this is where the one-shot law lives" at `:152–155`).
- Escalation record `ControlEscalationRecord` (`types.ts:526–541`) — the frozen five fields + `escalationSequence`, `createdAt`.
- Successor ladder: `CONTROL_ESCALATION_SUCCESSOR` (types.ts ~328–413) is rung→rung only (`leader-approval` case rises member… i.e. member→leader→human-user→`null`-at-top; `human-admin` ∈ `CONTROL_UNRESOLVABLE_AUTHORITIES` → `hasAuthorityResolver` `:397` false → A1-12 termination).
- Staleness: instance staleness re-checked at decision time (`:2671–2693`, writes `stale-denied`); scope staleness at consumption via snapshot match (`:3511` `scope-mismatch`); authority drift at consumption via A1-14 (see A5).

## A4 — Invariants inside the decision transaction; lock discipline

**`resolveControl` order** (all inside ONE `withTeamLock` hold opened at `:2591`; argument validation runs outside):
1. NOT_FOUND (`CONTROL_REQUEST_NOT_FOUND`)
2. abandoned ⇒ `CONTROL_REQUEST_ABANDONED` (abandon is the terminal mark, checked BEFORE decided, zero side effects) `:2605`
3. decided ⇒ `CONTROL_REQUEST_DECIDED` `:2612`
4. **role closure** `CONTROL_RESOLVER_ROLES[kind]` `:2622` — BEFORE case law and envelope (a refusal must not need authority the caller lacks)
5. `assertNoActOnEarlierLeg` (case law, A1-10) `:2642–2652` — only if `approvalCaseId` present
6. `enforceEnvelope(RESOLVE_CONTROL_SPEC, callerEnvelope(...))` `:2654` (fail closed; human unbounded — invariant 34)
7. instance staleness → commit `stale-denied` + throw `:2671–2693`
8. allow-only external hard-policy probe → durable `deny`/`external-policy` + throw (`:2696ff`) — external hard policy sits ABOVE human approval
9. PA manifest gate: `paManifestClassOf` corrupt ⇒ durable deny `authority-undetermined`; valid ⇒ awaited `paEffectsDenyReason('resolve', …, callerRefOf(caller))` refuse ⇒ durable deny (`pa-authority-drift` | `authority-undetermined`)
10. `commitDecision` allow/deny — the sole `control-decision-recorded` append.

**`escalateApprovalLeg`** mirrors steps 1–6 (role closure `:4852`, envelope `:4866`, case law `:4873`), then requires case fields (`:4845–4851` "pre-Alpha.4 row … no case to rise"), verifies the FROZEN identity is present before any write (`:4895–4913` — an invented beneficiary would split the case), then the 3 writes (A1 §6).

**`guardOperation` order** (one lock hold): malformed-argument checks → candidate collection → current-leg rule (`currentLegOf` `:4124`, `isLaterLegThan` `:4111`: a later-leg unconsumed allow governs, a superseded one does not) → per-candidate: `request-abandoned` block; `DECIDED`/`allow-consumed` blocks (`:3499–3510`); `scopeSnapshotMatches` ⇒ `scope-mismatch` (`:3511`); decision dispatch exhaustive with typed refusal default (`decision-unrecognized`); inline-coupling candidates skipped (lane disjointness `:3484–3489`); >1 unconsumed allow ⇒ `CONTROL_GUARD_AMBIGUOUS` never consuming (`:3521–3530`); live external hard recheck zero-consumption (`:3547–3557`); A1-14 `recheckConsumedAuthority` (`:3571`, impl `:3168–3238` — port verdict `still-sufficient|authority-risen|undetermined`, no port ⇒ `authority-undetermined` "a guard would be spending an allow it cannot confirm"); PA gate re-run in-lock with the DURABLE allow's decider (`:3595–3622` — corrupt class blocks with zero consumption WITHOUT any verifier); corrupt-leg last-look (`:3629`) — THEN the consumption fact (`:3630–3642`). Every refusal path is zero-write.

**Lock:** `withTeamLock` (`packages/runtime/action-router/effects.ts:316–356`) — per-root promise-chain serialization, non-reentrant, cancellation keeps the queue slot. The team lock is "a concurrency device, NOT authority" (invariant 45): every entrance re-reads durable state (`loadControlState`) inside the lock and never caches authority across holds. `closeZeroReviewCaseTransactionally` and `persistAbandonCloseLocked` exist precisely because the lock cannot be re-entered (`:5288–5346`, `:4026–4052`).

**Outside the lock:** `port.notifyLeaderRequest` fire-and-forget after `requestControl` returns (`:2535–2549`; option doc `types.ts:2010–2021` "INVOKED ONLY after the per-team lock is released"); argument parsing/validation; `resolveTeamAndTarget`/`resolveCaller`/`callerEnvelope` computation at the facades; the `awaitControlDecision` 250 ms poll (liveness bridge — durable rows remain the authority); the leader notifier renderer (`control/leader-notification.ts:80` render + `:163` createLeaderControlNotifier — "renders text only — NO decision authority"). NOTE: the awaited ports `authorityRevalidation` and `paEffectsVerifier` run INSIDE the lock by contract (PR358-B root ruling 6, `:3138–3141`).

## A6 — FEASIBILITY VERDICT: case-scoped ReviewMandate INSIDE the single write path, without widening CONTROL_RESOLVER_ROLES

**Verdict: FEASIBLE as a composed, ledger-derived case-scoped admission at the existing role-closure points — no rung change, no second store, no vocabulary change. It is a new CAPABILITY SHAPE, not a new authority source.**

Grounds:
1. **The durable vocabulary already admits a member decider.** `ControlCallerRef` (types.ts:1565–1567) and `parseCallerRef` (`service.ts:518–538`) accept `{kind:'instance',instanceId,role:'member'}` as a decision-row `decider`. `CONTROL_RESOLVER_ROLES` needs no edit (C1-safe, and the ladder types `ProposalAuthorityPosition` are untouched).
2. **The law the mandate check implements is already written in the spec.** Spec §7.4 (`alpha4-permission-governance-spec.md:305`): `mayReview(reviewer, case) who may act = ladder position + case.requiredAuthority`; legality `= mayReview AND desiredEffect <= grantCeiling(reviewer, scope)` (`:310`); §11.5's action table is per-case; §24.4 (`:1072`) requires the ONE write path to "re-derive the caller principal, the leg's reviewAuthority, and the legal action set". The current implementation realizes `mayReview` only as the carrier-kind role table (A2) — a case-scoped mandate check lands exactly in this spec-law/gap, i.e. it NARROWS toward the written law rather than adding a new rung or authority.
3. **In-lock composed checks already have two precedents:** `options.authorityRevalidation` and `options.paEffectsVerifier` (types.ts:2045/:2058) are injected, awaited-inside-the-lock, closed-vocabulary verdict ports (`service.ts:3147–3166`, `:3168–3238`). **BUT both are refuse-only** — they can veto, never admit — and on the resolve path they run AFTER role closure (`~2700ff` vs `:2622`), so a member caller dies at `:2622` before either port is consulted. The mandate check must therefore be composed AT (or immediately merged with) the role-closure point, not downstream of it.
4. **There is NO existing actor-vs-principal / "on behalf of" / delegated-resolver distinction anywhere in the control plane.** The only splits are `requester` (who asked) vs `decider` (who decided), and `beneficiaryAuthority` (whose authority rises — explicitly "not reviewer", types.ts:1667–1668). The one ownership-scoped-authority precedent is `mayAbandon` (`:1629`, member ⊇ own rows only) — proof that per-case/per-ownership admission inside the service is an existing pattern, though abandon is not a decision.

**Exact change points (minimal compatible extension):**
- Compose the admission predicate at the four closure sites: `service.ts:2622` (resolveControl), `:4852` (escalateApprovalLeg), `:5228` (appendTerminalOutcome), `:5495` (closeApprovalCaseWithoutLeg — Alpha.6 must decide whether a mandate may close; the site's comment already ties it to the deny-only asymmetry). Admission becomes: `CONTROL_RESOLVER_ROLES[kind] ∋ caller.role` **OR** (`row.approvalCaseId !== undefined` **AND** a case-scoped ReviewMandate, folded from ledger facts inside the same `loadControlState` pass, binds `callerRefOf(caller)` to THIS case — holder identity, permitted action subset (allow/deny vs escalate?), and scope ceiling all checked in-lock).
- **The mandate must itself be a TeamDomain fact family** (new kebab-case family, e.g. `control-mandate-granted/revoked`, written through the same `putEntry` under the same lock by leader/human only, payload closed and derived like every other payload). `ApprovalCaseState` (types.ts:548–571) has NO assignee field today — it must gain a derived `mandates?` slice in `buildApprovalCaseState` (`:4363–4530`), preserving A1-17 (derived view, no case row). This keeps C2 (one store, one fold) and C3 (the fact BINDS the case; the authority to act is computed from the closed mandate law at decision time — assignment alone decides nothing until the write path's composed check runs; enforcement of C3 = the mandate payload carries no un-declared authority, and the check happens per-decision, fresh, in-lock).
- **Non-cases must NOT get the OR-branch:** the compose is gated on `approvalCaseId !== undefined`, so legacy rows, pre-v3 rows (`pre-execute-adapter.ts:1946–1963`) and PA-bridge rows (legless; `tadm:` id only inside `reviewPayload`) keep today's role-table-only behavior. This is what a widened `CONTROL_RESOLVER_ROLES`-with-member CANNOT give: a widened table would admit members on legless rows where no mandate can attach — which is why table-widening is the wrong shape even setting C1 aside.
