## World-shape finding (the key verification, parent-adjudicated)

The STOCK P6T4 world seeds the leader row in the P6-era **v1-style**:
`p6t4Seed('leader')` (p6t4-helpers.ts) carries
`childSessionId: 'session-child-p6t4-leader'` AND `lifecycle: 'RUNNING'`;
the contracts union factory (`isLeaderInstanceRecordInput`,
packages/contracts/src/dto/member-instance-record.ts) routes to the v2
LeaderInstance mint only when BOTH keys are ABSENT — so the stock row
stores as a v1 member record. Verified empirically (see red-unfixed.txt):

```
STOCK_WORLD_LEADER_ROW {"present":true,"schemaVersion":1,"hasLifecycleKey":true,
  "lifecycle":"RUNNING","hasChildSessionIdKey":true,"childSessionId":"session-child-p6t4-leader"}
```

On that stock row the unfixed guard returns `allowed: true` (RUNNING ∈
GUARD_LIVE_LIFECYCLES) — the bug is masked and a stock-world suite would
not discriminate. Production mints the v2 shape (P8-S2 root-binding mint;
invariant 15). The suite therefore replaces the world's leader row with
the production shape through the world's own PUBLIC repository API only
(`memberInstances.delete` + `put` with an honest LeaderInstanceRecordInput
— no storage-level writes, no bypassed validation); `p6t4-helpers.ts` is
unmodified.

**Exact stored leader-row shape used by the suite** (fresh durable read,
pinned by the suite's own assertion):

```
{"schemaVersion":2,"hasLifecycleKey":false,"hasChildSessionIdKey":false,
 "keys":["activityVersion","createdAt","instanceId","label","rootSessionId",
 "schemaVersion","templateId"]}
```

The ordinary member rows (worker) are used untouched (A6-T3).
