## Classification: committed-recipe defect (test asset), NOT product / credentials / host / browser

1. **Frozen product semantics** (`packages/runtime/control/service.ts` L923-955, `resolveControl`):
   the external hard-policy gate runs for `decision==='allow'` only when
   `capabilityDomain = payload.capabilityDomain ?? (payload.toolName !== undefined ? 'tools' : undefined)`
   is DEFINED. A request with neither an explicit `capabilityDomain` nor a `toolName` has
   `capabilityDomain === undefined` → the policy check is skipped → the allow commits plainly. This is the
   frozen behavior (Architecture §25.4 / invariant 34; unchanged by the F9 repair — frozen contract L173/L436).
2. **Every request generated by the committed recipes lacks toolName**:
   - `b4-requests.md` (boot#1): 4 requests, all `action=write`, no toolName (payloads seq 3-6: toolName absent).
   - `b6-req.md` (boot#2): 1 request, `action=write`, no toolName (payload seq 14: toolName absent).
   Therefore NO request in the r2 world can ever be blocked by `externalPolicyFacts.hard.tools=deny`;
   any human/leader allow on any of them commits as a plain allow. The G4 gate's expected outcome
   (deny + external-policy + "Execution: Blocked by managed policy") is structurally unsatisfiable
   under the committed recipes on any boot, boot#1 or boot#2.
3. **The V1 precedent the gate models declared toolName** (`tests/mock/evidence/NOTES.md` T4.7a, L201):
   `team_request_control {requestToken:"dtest-t47-hard-correlation", kind:"leader-approval", ...,
   actionName:"write: hard-tools probe", toolName:"write"}` → capabilityDomain derived as `'tools'` →
   `CONTROL_EXTERNAL_POLICY_DENIED` → durable `deny · external-policy` (V1 domain seq 114) → UI row
   "21:10:35 控制裁决 W1 — deny · external-policy" (T4.7b PASS). The committed V2 recipe `b6-req.md`
   dropped the `toolName` parameter relative to that precedent, so the F9 G4 flow can no longer reach
   the policy branch it was written to gate.
4. **Secondary, vacuous-assert note (committed gate config, not a world defect)**: the error-chip
   assert `errs.every(e => e.getAttribute('data-resolve-error-code') === 'CONTROL_EXTERNAL_POLICY_DENIED')`
   returns true for an EMPTY chip list; at capture there were zero error chips, so that PASS proves
   nothing. The gate's discriminating asserts are the decision-row and bar-removal asserts, which failed.
