## 1. What M2 exposes; what remains unproven

M2 did **not** assemble or wire an A-identity-binding governance layer. Definitions A and B were registered, swapped, and restored by the same plugin. Therefore M2 does not show that an implemented control breaks **CI-04** or fails **CI-05**. CI-04 is a requirement on the future governance layer: the current execution binding must be proved by the trusted Host Scope’s actual Definition/Binding identity (`docs/plans/memo/alpha5-reset-20261025/center-assembly-architecture.md:30` @ `1310b959`). M2 exposes that the pinned primitive does not itself supply that property: after the pre-dispatch name/argument gate, dispatch performs a fresh live name-to-Definition lookup at `tests/deepseek-harness-test-use/packages/core/tools/src/index.ts:1578` and invokes the resolved body at `:1581` @ `639ed015397290b3745d163aafe02ffee4aa3f84`. The architecture requires zero invocation of an unverified Definition after replacement (`.../center-assembly-architecture.md:122` @ `1310b959`); protection for that CI-04/CI-05 mechanism-level requirement is therefore **NOT PROVEN / UNTESTED**, not a demonstrated invariant violation.

This is **not an authorization bypass**. The pre-dispatch gate/guard decides from the execution name and arguments (`tools/src/index.ts:1493-1519` and guard restriction object `:700-711` @ `639ed015397290b3745d163aafe02ffee4aa3f84`); M2’s own scope note says no authorization check is bound to Definition identity (`dev/agent-workflow/evidence/s1-h0-m2/runs/s1-h0-m2-2026-10-24T23-26-02Z/summary.json:56`).

M2 first-hand established only the raw late-resolution behavior: inside the real `tools/execute` fence, same-name A→B replacement made call #1 run B, including marker/read/process legs, and restoration made call #2 run A as control (`.../ledger.jsonl:2-16`; `summary.json:24-30`). The sealed run is **FAIL as recorded** because two oracle result-delivery checks were false (`summary.json:31-35`); the host session record separately says both results had `isError:false` and the model issued call #2. Wire request bodies were not persisted, so wire shape/result delivery is **UNKNOWN**.

Related invariants remain **UNTESTED**: CI-06 (single PA/Control/Grant authority), CI-07 (complete effects under one authorization judgment), CI-08 (ordered cancellation/unload and old-disposer/new-mount behavior), CI-09 (settlement/no post-effect retry and uncertain remote terminal state), CI-10 (independent Domain veto), CI-11 (dynamic-source closed-world admission/collision/alias protection), and CI-12 (fixed release provenance) (`center-assembly-architecture.md:32-38` @ `1310b959`). M2 also did not test Scope/Binding-generation changes, nested calls, or a pre-body rejection of a swapped Definition.

## 2. Public API prevention point, residual window, and candidate status

`ctx.tools.get` is public and returns the currently visible Definition: `get(name, scope?) → this.view(scope).visible.get(name)` (`tests/deepseek-harness-test-use/packages/core/tools/src/index.ts:1221-1232` @ `639ed015397290b3745d163aafe02ffee4aa3f84`). Its view honors scoped shadowing and restrictions; the comment says the result is the definition the scope resolves. Dispatch uses `resolveExecution(exec.name, exec.agent, exec.parent !== undefined)` (`:1234-1240`, `:1578`), which applies the same scope/visibility view but additionally applies operation-mode collapse for model-direct versus nested calls. Consequently `get(name, exec.agent)` is a useful current-definition observation for the ordinary matching mode, but it is not an immutable approval token and can disagree with dispatch if mode/parent semantics differ or if registration changes between reads.

A public `tools/execute` listener can decide before any body by running synchronous/pre-`next()` logic: the execute waterfall is outermost-first and a listener that does not call `next()` vetoes the rest, including built-in dispatch (`vendor/cordis/src/events.ts:224-243` @ `639ed015...`; registration uses push/unshift order at `:254-259`). The actual residual window is precise: `dispatchToolBody` checks abort at `:1572-1575`, then resolves at `:1578`, sets `bodyInvoked` at `:1580`, and invokes at `:1581` with no await between resolve and invoke (`tools/src/index.ts:1564-1583`). A listener can therefore compare a current `ctx.tools.get(exec.name, exec.agent)` result before calling `next()`, but a same-name replacement can land after that `get` and before `:1578`; an earlier/other execute listener’s await can create that interval. A plugin cannot assume it is the last listener: listeners are ordered by registration, and later registrations are part of the same waterfall chain (`events.ts:224-243,254-259`).

`tools/change` is synchronous and unparameterized: registration-layer changes call `this.ctx.emit('tools/change')` (`tools/src/index.ts:208, 833-835`), while the event is declared `() => void` (`:200-208`). Cordis `emit` maps listeners synchronously in order and does not await returned promises (`vendor/cordis/src/events.ts:189-196`); a thrown listener exception propagates from the map callback, but registration has already changed and later listeners/order are not a reliable transactional rollback. A plugin cannot guarantee being the last change listener; registration order controls listener order (`events.ts:254-259`). Thus a change listener can synchronously abort a call **only when** its abort reaches the dispatch abort check before `:1578`; this is prevention in that timing, not proof of identity binding for every swap.

Prior candidate evidence confirms this conditional distinction rather than proving impossibility. The historical B3 matrix records a signal-wrapper plus `tools/change` abort route that preserves the execute chain and relies on the host abort check at `:1572` (`dev/agent-workflow/evidence/alpha5/pr1r/b3-options-side-effect-matrix.md:84-91,126-130`). The G-g contract records that a delivered change can cancel an in-flight call before body, while a subscribed-but-never-delivered channel permits the moved body to run and only yields settled-edge alarm/detection (`dev/agent-workflow/evidence/alpha5-pr1r/g-g-support-contract.md:30-38,55-65,90-107,114-118`). Its status remains UNSUPPORTED/待证 for the silent channel, not a universal prevention claim. The older PR1 snapshot evidence is storage/identity-generation testing, not proof of Host dispatch identity binding (`dev/agent-workflow/evidence/alpha3-pr1-permission-overlay/RECAP.md:24-86`; `snapshot-id-bound-green.txt:4-16`; `snapshot-id-bound-red.txt:12-29`).

**Candidate status: CONDITIONAL / UNPROVEN.** One legitimate testable candidate exists: a public `tools/change`-armed abort guard that (1) records the current Definition object from `ctx.tools.get(name, exec.agent)` for the call, (2) synchronously aborts the call when a same-name registration change is delivered, and (3) relies on the host’s `:1572-1575` abort check to prevent body entry. Preconditions are that the change event is actually delivered, the call is still before `:1578`, and the guard’s name/scope filtering matches the dispatch mode. Success is zero B body invocations and an explicit pre-body abort; failure is B body invocation or a silent/no-delivery arm. This candidate does not prove A identity binding when delivery is absent or when the swap occurs after the abort check. No experiment was run.

Candidate signals classified: pre-execute name/argument denial is prevention only for that predicate (`packages/hooks/hooks-claude-code/src/index.ts:244-250`); `tools/change` abort is conditional prevention when delivered before `:1578`, otherwise detection/response (`g-g-support-contract.md:30-38`); armed flags, alarms, and settled-edge audits are detection after/concurrent with the fact (`g-g-support-contract.md:17-21,31-33`); output-schema validation is post-body (`tools/src/index.ts:1832-1835`).

## 3. Determination and required ruling

**UNPROVEN / NEEDS-RULING.** The public API exposes a testable conditional route through `ctx.tools.get` plus synchronous `tools/change`-triggered abort, but the cited Host behavior does not establish that this route closes the residual get→resolve window or guarantees event delivery/order. The open user decision is whether the safety claim may be conditional on delivered change notifications and a pre-`:1578` abort check, or whether CI-04/CI-05 require an unconditional atomic Definition-identity binding at dispatch. This review does not patch Core/Host or alter the plan.
