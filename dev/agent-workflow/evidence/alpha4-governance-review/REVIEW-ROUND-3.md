## Why this merges without a fourth review

The plan caps review at three rounds per PR (ADR A1.1, and round 3 was announced as the last permitted round). Both lanes' `CANNOT MERGE UNTIL` lists are enumerated above and each item is now closed **in the text an implementer executes from**, not by pointer — which is what Global Precedence rule 3 demands — and each was re-verified against the repository by me rather than accepted on assertion (two of my own A4 premises died in that pass, along with the `escalate`-as-decision-value line and the phantom §21.1 quote).

What is *not* obtained by this: an independent confirmation that A5's positional ceiling model is the last word on the security question. It is internally consistent with ADR §15, §3.2, spec §21.6 and the plan's own pinned test line, and it closes round 2's hole by a different law than the one it replaces. The mitigation is structural rather than procedural: **PR2's lane-A ceiling-reachability matrix is a blocking RED-first test written before the algebra**, it pins all four reviewer positions and the `undetermined` case, and PR2 carries a targeted security reviewer of its own. If PR2's matrix cannot be satisfied by A5-1, that is the point at which the model fails, and it fails as a red test in the first hour of PR2 rather than as a merged document.

Round-3 disclosures that stay open on purpose: the real-host and Chrome acceptance lanes remain environment-blocked (A1.5, pre-adjudicated); PR0a's RED test has not yet been executed (it is step 1 of the fix); and `A5-20`'s audit gap is a design trade-off, not a defect.
