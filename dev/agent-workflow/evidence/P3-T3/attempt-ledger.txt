## Blocker — canonical chain cannot pass

Seam: the frozen P1-T4 tsconfig trio for the domain package:
- `packages/domain/tsconfig.json` (FROZEN, P1-T4): `extends ./tsconfig.build.json`, `noEmit: true`, `rootDir: "."`, `include: [src, test, vitest.config.ts]`
- `packages/domain/tsconfig.build.json` (FROZEN, P1-T4): `extends ../../tsconfig.base.json`, `rootDir: "src"`, `outDir: "dist"`, `include: [src]`
- `tsconfig.base.json` (FROZEN, repo root): `declaration: true`, `declarationMap: true`

Required behavior: `tsc -p packages/domain/tsconfig.json` passes for any domain code that imports
contracts v1 — which TaskDoc §11.4 mandates ("Allowed deps: contracts v1 ONLY") and which every P3
domain task (P3-T2/T3/T4/T5) therefore does.

Observed behavior: 18× `error TS6059` — contracts `src/**` files are in the program (imported via
the sanctioned relative `.js` specifiers; see below) but outside `rootDir: packages/domain`, while
`declaration` (inherited via the frozen build config) is enabled. Exit code 2. Zero other error
codes: all domain source and all 70 t3 tests typecheck clean.

Minimal reproduction: any file under `packages/domain/src/**` or `packages/domain/test/**` with
`import { deepFreeze } from '<relative path>/contracts/src/index.js'` (the only runtime-viable import
style — contracts `package.json` exports point at `./dist/*`, which is unbuilt and must not be built
per task red lines; package-name imports fail identically in tsc with TS2307 and in the plain-node
runner with missing `dist/index.js`), then `node node_modules/typescript/bin/tsc -p packages/domain/tsconfig.json`.
Verified on base `39a5d22f` skeleton: the base package program is contracts-free and clean; the seam
activates the moment the mandated dependency is imported.

Why no owned-path fix exists: the three files that would fix it are all outside P3-T3's owned paths
(they are the P1-T4 frozen skeleton / LOCKED_SURFACE). Alternatives rejected: building contracts
`dist` (forbidden), vendoring/copying contracts sources into `packages/domain` (forbidden; creates a
divergent copy of a frozen contract), type-only imports (domain needs runtime values: `deepFreeze`,
parse functions, `teamContractError`, `LEADER_INSTANCE_ID`, `assertInstanceIdUniqueWithinTeam`).

Affected invariant: TaskDoc §11.4 canonical chain (package tsc leg) for every P3 domain task.

Proposed fix (for the skeleton owner / integrator; a CONTRACT_CHANGE_REQUEST against P1-T4 is the
protocol path per ROUTER_RULES §4.3): make the noEmit typecheck config not conflict with
cross-package source imports, e.g. (a) drop `rootDir` from `packages/domain/tsconfig.json` (the
noEmit typecheck config), or (b) add `"declaration": false, "declarationMap": false, "sourceMap": false`
to that config only, or (c) have the skeleton provide per-package `paths`/project references to the
contracts sources. Any of the three makes the canonical chain pass on the current P3-T3 tree
without touching domain code.

Classification note: reported as `CORE_SEAM_BLOCKER` because the task card names it as the blocked
status and `structured_output` offers `BLOCKED_CORE_SEAM` as the only blocked status; the precise
protocol vehicle for the fix is a `CONTRACT_CHANGE_REQUEST` against the P1-T4 LOCKED_SURFACE
(tsconfig trio), not an upstream DSH patch (no upstream behavior is missing).
