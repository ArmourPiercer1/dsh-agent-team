# tests/doc-consistency — ownership and controls (EB1)

**Owner: Engineering Baseline line (E0–E1).** Created 2026-10-23, isolated branch
`task/eb-e0-e1-doc-baseline-20261029`, base `929fc4af2`. Nothing here is collected
by `vitest.config.ts` or by `scripts/run-tests.mjs`, so the nine-root Census and
the Alpha.5 red sets are untouched by this directory.

## What runs this code

| target | command | what it proves |
| --- | --- | --- |
| positive + negative controls | `pnpm docs:controls` | every rule below can FAIL for the right reason, and the clean baseline PASSES |
| fast probe | `pnpm docs:probe -- --base <verified-ref>` | changed-document consistency (T0) |
| complete check | `pnpm docs:sync -- --check` | whole current-document set, including derived-view freshness |

Controls are run by a plain-Node runner (`scripts/doc-consistency-controls.mjs`),
not by the suites, because this worktree has no `node_modules` by design (capacity
rule for this line). They are also read-only against the repository: each scenario
gets its own throwaway fixture Git repository under the gitignored
`.worktrees/eb1-controls-scratch/` path of this worktree. Nothing is written into
`docs/`, `.agents/` or `dev/` by a control.

## Six things this harness has already caught in its own tooling
1. **A patch that hit two identical anchors.** Wiring `checkRatification` into
   `docs-sync.mjs` by string replacement matched both `const built = buildStateView(root)`
   sites — inside `check()` and inside the `--write` CLI branch — so `--write` threw
   `ReferenceError: findings is not defined`. 26 controls reported FAIL, not PASS, because
   a crashing scenario is a failed control. Fixed by removing the stray line.
2. **A green that was really a crash.** Earlier, on 2026-10-23, a helper deleted by
   dead-code cleanup made a control exit 1 for the wrong reason; it nearly got logged as a
   passing negative control. `expectRun` therefore rejects any output containing crash text
   even when the exit code matches.
3. **A safety check that ran after the early exit.** `docs:sync --write` compared the
   rendered view with the file on disk *before* validating the location, so a target
   replaced by a symlink answered "already fresh" and exited 0 with the boundary never
   consulted. NEG-27 caught it; `checkGeneratedTarget()` now runs first, and the
   nothing-to-do case prints an explicit no-op instead of wording that implied a verified
   write.
4. **A wildcard rule that matched nothing.** The glob translator escaped dots *after*
   expanding `**` into `.*`, producing `\.*` — no path matched, so every wildcard owner rule
   was dead while the exact-path control kept passing. POS-9 / NEG-40 test matching across
   directories and the refusal to cross a separator.
5. **A schema describing rules nobody enforced.** `registry.schema.json` claimed
   `additionalProperties: false` while the validator accepted any field, listed `refs` as
   required when it never checks it, and had no entry for the claim fields the validator
   reads. A second top-level `entries:` also restarted the list silently, because that key's
   branch continued before the duplicate check could see it. The field set is now closed
   (`REGISTRY_UNKNOWN_FIELD`), a duplicate names the exact key, and `checkSchemaAgreement()`
   now compares the two on every run — the keywords the schema uses (required, enum,
   pattern, additionalProperties) are read straight from the validator's own constants, so
   drift is a finding (`SCHEMA_ENUM_MISMATCH` and siblings) rather than a review catch.
   The commit-field rule is one constant, not two: `COMMIT_REX` is what the claim checks
   execute (40 hex, because the value has to name a commit object — an abbreviated hex
   cannot) and `COMMIT_RE` is that same rule read as a source string for the comparison, so
   the documented pattern cannot quietly be looser than the enforced one. The first thing
   the comparison caught was in the alignment commit itself: the documented
   `verified_tier` values were the `verification_status` vocabulary, while the validator
   accepts `C1|C2|C3`.
6. **An assertion weak enough to survive a WARN.** `rc == 1` plus "output contains
   CLAIM_UNBOUND" is satisfied when that code appears only as a non-blocking WARN and the
   exit code came from something else. `expectBlocking` reads the printed classification
   instead and reports the whole blocking set in the reason line.


A scenario passes only when the expected finding code **and** the expected exit
code are both observed; an unexpected crash is reported as a FAILED control, never
as a pass (learned the hard way on 2026-10-23, when a `ReferenceError` exit 1 was
almost logged as a successful negative control).

## Which refusals this line imposes on itself

`dev/engineering/doc-ownership.yaml` may mark a rule `enforce: true`. For those rules
only, changing the source without changing its declared owner document is a blocking
`DOC_OWNER_UPDATE_MISSING`. Five rules carry the flag, and every one of them names a
document this line owns (`tests/doc-consistency/README.md`, `dev/engineering/README.md`,
`.agents/notes/README.md`, `docs/terminology.md`) — including `scripts/generated-write.mjs`,
which previously fell through to the catch-all `scripts/**` rule whose owner is
`docs/STATUS.md`, a document this line is not allowed to edit. A rule pointing at a file
you may not touch is not an owner; that gap was visible only once the flag existed.

The flag is deliberately absent from `packages/**` and the catch-all rule. Making other
people's changes carry this line's documentation preference would be a gate on them, and
this branch has no authority to place one. `docs:probe` reports the rest as
`DOC_IMPACT_OWNED` / `DOC_IMPACT_UNOWNED` coverage, unchanged.

## Deliberately NOT covered here (declared, not hidden)

- No C1/C2/C3 and no runtime behaviour: these are static document checks.
- Claims inside Markdown table cells are not scanned (policy tables produce false
  positives); a table containing a delivery claim is missed.
- Historical text (round log, `evidence/**`, finished plans, frozen contract
  records) is preserved and never retro-flagged.
- Semantic equivalence of prose stays with the Contract Owner.
