## 0. 不可妥协的阶段出口

### 0.1 必须完成的目标

1. **全可分发工具受控**：对固定 DSH Host、当前产品配置与所有已声明 Team 配置，所有可能从 Team Agent 到达实际 Body 的分发入口（预设继承、Team 自有、Agent Scope 注册、动态 MCP、复合 PTC 子调用、Jobs、LSP 与受信 Provider）必须具有可信、可核验的路由和权限归属。未识别或未绑定的工具在进入副作用边界前拒绝；任何原生 Body 回落都是阻断项。
2. **正常工具功能可用**：属于 Alpha.5 需求范围的每类工具，必须至少在其已声明、可实施的正常权限配置中完成真实执行、允许/拒绝/Ask（适用时）、结果呈现与生命周期验收。**仅 Guard 全拒绝、仅装配为 DORMANT、仅测试工装 GREEN，不能算工具接管完成。**
3. **单一审批权威**：复用 Alpha.4 durable ApprovalCase 与 Authority Ceiling；统一 Operation Admission、不可重放的单次 Grant、执行前失效复核；不增加平行授权账本，不让模型参数成为受信 Principal/Grant。
4. **逐维保证可信**：工具级 allow/ask/deny 与文件读、文件写、网络等效果维度正交；由 Provider/OS 在真实执行边界兑现已声明保证。不支持的具体能力组合必须明确拒绝，绝不伪装成安全的原生回退。
5. **固定产品形态可安装、可验收**：最终 C3 验收针对同一精确产品 SHA、对应安装产物和固定 Host Pin，完整覆盖工具矩阵及关键跨工具负控，给出可复跑的 machine-readable 终判。

### 0.2 不能把「安全拒绝」偷换为「工具交付」

逐工具结果区分以下两条独立事实：

- **治理闭合（CONTROLLED）**：该入口已接管或可信截断，无法绕过统一政策；未授权效果为零。
- **正常能力闭合（FUNCTIONAL）**：承诺的该工具正向业务功能在合法策略下可运行，返回值与宿主契约相容。

进入 Alpha.5 完成集需要两者同时成立。若固定上游 Host/OS 不提供某种强化保证（例如全协议网络 deny、完整 metadata 不可见），可在**能力维度**标记 `UNSUPPORTED/BLOCKED` 并运行时先行拒绝；但只要它属于已承诺的 Alpha.5 必交功能，就仍是 **RELEASE BLOCKER**，除非用户明确修改需求或授权新的 Provider/工具级 fork 路线。**不允许执行体自行把未实现工具整体降为 Unsupported/Deferred 以通过发布门。**

### 0.3 明确的非目标

不设置 Alpha.5 试用阶段、子版本试用放行或以试用候选代替阶段出口；不启动 Alpha.6 Leader/Review 分离；不重新实现 Alpha.4 权限主体；不修改上游 DSH Core（`CORE PATCH BUDGET = 0`）；不引入没有实例与上游证据支持的新权限概念；不为获得「全绿」降低关键安全测试标准。

## 1. 基线、事实输入与冻结顺序

### 1.1 统一输入（M0 开始时冻结一个事实截面）

- 代码真值：远端 `master` 精确 SHA + install/dist 构建对应关系；Host 真值：`tests/paths.mjs` 的固定 DSH Pin、公开 API 与注册/执行接缝。
- 能力真值：Dot 交付的逐工具矩阵。每行至少记录：`工具名／来源和实际可分发条件／原生 Body／当前 Adapter／实际生产 import+placement+dispatch 边／Effects／授权和 I/O 范围／Provider／取消与重启语义／已有 C1、C2 证据／缺口／归属／必交程度`。**必须穷尽实际 dispatchable 面，不只看 model-visible schema。**
- 需求真值：2026-08-29 冻结文档、Alpha.4 已裁语义、Alpha.5 ADR §8 与技术方案、用户此次关于「所有工具可靠接管、不接受有限试用」的最新裁决。
- 欠债事实：仅以当前代码、可定位的真实 Host 证据、已合并 PR 的实际代码为依据；历史 `DORMANT`、`LIVE`、`GO` 等快照一律不得直接升格为现状。

**M0 的首个可交付**是一份简短的「契约差异裁决表」：按工具列出 `原要求 → 当前实现 → 保留/修正/上游阻断 → 精确验收`。只更改工程接口和经过用户批准的需求边界；不能因实现困难自行削弱原安全要求。

### 1.2 冻结优先级

先冻结：①统一授权/身份/Effects/Grant 不变量；② Adapter 与中心装配接口；③每工具族必交能力与特例接缝；④最小 C1/C2/C3 判据；**最后**才允许任何并行重构 PR 修改公开接口。

已有模块可继续复用，不允许为追求「统一」而重做 Guard、Controlled FS、Confined Process、Provider Gateway 或 durable approval。每个新抽象必须指向一个当前可复现的重复责任/无法并行开发的接口矛盾，否则不引入。

### 1.3 接口冻结后的变更控制

- 冻结结果包括机器可检查的类型/Schema、错误分类、示例调用与 fake Provider contract suite（具体导出名称由 M0 决定，**本文件的概念名称不视为现有代码 API**）。
- 冻结接口有**唯一 Owner（中心装配 Lane）**。工具 Lane 不能自行扩展或局部覆写接口。
- 必须改变接口时提交 **Contract Change Request**：提供真实 Host/最小反例、哪些工具受影响、权限是否放大、替代方案、迁移/回归成本、唯一决策结果。若改变安全语义/必交范围，升级到用户裁决；仅明确的兼容性扩展由中心 Owner 审定。
- 变更合并后统一提升契约版本，受影响工具在同一集成窗口内修改；不得一个工具偷用 v2，另一个静默留在 v1。

## 2. 冻结的 Adapter–Assembly 责任契约

### 2.1 中心只做跨工具的事

**中心装配所有权**：可信 Agent/Team 身份、Scoped Registry 与稳定 Definition Placement、Binding 修订/验证、Closed-world Guard/Mask、Operation Admission、Alpha.4 ApprovalCase 与 single-use Grant、按保证选择 Provider、在途 ExecutionLifetime/Lease、撤销/重启与审计、install 入口。

**工具适配所有权**：工具本身的名称与原生参数/Schema、每个子命令的 canonical Effects、前置参数验证、对可信 Provider 的实际调用、原生行为/输出/Spill 的等价与有界差异、工具特有的子进程/服务/Job 生命周期、工具级负控。

中心不得包含逐工具硬编码的业务 parser/renderer/argv 构造；Adapter 不得自行实现第二套 durable 授权和作用域查询。中心只能消费 Adapter 声明和可信执行接口，不能从模型字段猜 Scope 或 Grant。

### 2.2 最小接口语义（概念契约，M0 提供实际类型）

`ToolAdapterDescriptor` 应声明 `family / stableName / provenance / hostCompatibility / executionBoundary / effectClassifier / requiredCapabilities / outputContract / lifecycleHooks`；每次调用按顺序：

1. **Resolve & bind**：从已放置 Definition 与 Host Scope 获取可信执行身份，未绑定则拒绝。
2. **Classify**：Adapter 纯解析参数，产出完整且确定的 requested Effects；解析不确定时拒绝而非默许漏项。
3. **Authorize**：中心复用统一 Policy、Ask/ApprovalCase、一次性 Grant；批准范围不得被部分收缩后偷偷执行剩余效果。
4. **Prepare**：由可信 Provider 将已批准 Scope/Effect/能力要求落实到实际执行环境；不受支持的 Guarantee 在 Body 前拒绝；Domain Gate 在实际外部效果处独立否决。
5. **Dispatch**：经过最后一次 Binding、Generation、Grant、Provider 和取消/生命周期复核后，执行稳定 Definition。只使用已验证后端，不存在原生 Body fallback。
6. **Settle**：明确未执行、已执行（可能有副作用）、终止/撤销请求、终止未确认等互不混淆的结果；工具 Adapter 按真实 Host 的 output/schema/render/presentation 约定交付，不允许把失败渲染成空成功。
7. **Dispose/Recover**：先拒新请求并维持 mask，安全排空/撤销在途调用，再释放资源；动态注册、策略代际变化、重启都重新校验绑定。

所有异步调用必须承载不可猜测、不可跨 Agent/Realm 重用的可信调用上下文；任何 one-shot Grant 不得暴露给模型作为可重放 Bearer。对已经产生副作用的调用绝不自动重试，也不把 cooperative abort 声称为 OS 强杀。

### 2.3 不强迫特殊工具伪装为普通同名 Adapter

必须统一**治理语义**，不要求所有工具采用完全相同的注册机制。M0 按实际 Host seam 为每个特殊族选定技术路线：

| 工具族 | 专项装配约束 / 必须判定的接缝 |
| --- | --- |
| FS（read / read_image / write / edit / str_replace_editor） | 精确子命令 Effects、可信 Controlled FS、授权前零文件效果、旧内容保护、路径别名与读窗口等原生语义 |
| grep / glob | 受限真实搜索进程、rg 等价、无匹配/错误/大小上限/Spill/退出码/取消与输出一致性 |
| bash / pwsh | 进程树/FD/网络/读写边界、批准后执行、退出/超时/后台 Job 生命周期；OS 分别声明支持 |
| run_code / PTC | 保留 Host 复合 Transport 时通过可信外层 Runtime/Provider 和每个内层 tools.* 二次治理；不得强行同名注册被 Core 禁止的名字 |
| LSP | 真实客户端与 per-Member/Realm/Policy 生命周期、已启动服务的授权失效、子进程强制、protocol 请求结果；不以 fixture 或非 LSP tsserver 行替代完整声明 |
| Web / Remote / Domain | 本地 Team 准入与受信外部 Provider/Domain 最终判定分开；Redirect/DNS、远端执行权限只声明实证范围，不声称本机沙箱覆盖远端 |
| Jobs | 创建与管理权限、可信 owner/Member 归属、listing/output/kill 跨成员隔离、取消请求与真正终止区分、重启恢复 |
| MCP 动态工具 / 其他原生或 Team 工具 | 动态创建/撤销、scope 名称碰撞、native definition 身份、stdio 子进程或 HTTP 远端边界；扩张时重新进入 closed world |

上表是**实现 Lane 分类，不是穷尽清单**。Dot 的实际全量矩阵必须逐个定位到对应 Lane，包括未来出现或默认关闭但可被配置开启的工具。某个特殊 Host seam 不存在时，执行体须一次性给出 `CORE_SEAM_BLOCKER` 的最小反例与候选替代，不能以重复 PoC 无限搜索；是否调整产品需求由用户裁决。

## 3. M1：中心接口骨架先行（Plan B 的启动门）

### 3.1 只拆新增工具治理装配，不整仓重写

先在受控的中心 Lane 内，从当前 `packages/runtime/src/plugin/live/agent-bindings.mjs`、`team-tool-plane.mjs` 抽离 Alpha.5 的跨工具职责：Placement/Registry、Admit/Grant、Provider Resolution、Lifecycle/Dispose、通用错误/结果路由。使用小型 composition root 对接现有 Agent Setup；可新增局部模块目录，实际文件名在 M0 定；**不重写** Alpha.4 权限持久层、Team 主数据模型、已有 Provider 安全算法。

如果行为迁移需要短期桥接，桥接必须有唯一 Owner、明确移除检查和相同 C1/C2 正负控；不能保留第二套可独立决定权限的旧管线。

### 3.2 M1 必须交付的最小执行纵切

采用当前已相对可测的**受治 read + confined bash** 作为两条具有不同 Effect/Provider 的参考工具，再加一个「配置不支持→Body 前拒绝」的负向纵切：

- 使用**真实 Host public 注册/派发**，而不仅是 factory mock；验证 Agent own-scope Placement、definition identity、policy/ask/one-shot grant、实际执行边界、render、撤销。
- 一条 FS 正向/负向、一条 Process 正向/负向、一条不支持配置 fail-closed；跨两个 Member 至少有一组授权隔离负控。
- 未提供 `teamToolPlane` 的现有宿主世界保持原行为（零默认能力翻转）；无意触及非 Team Agent。
- M1 需通过 C1 基础、M1 专项 C2 和 install manifest/committed dist 一致性，才允许其他 Lane 在此骨架上开始并行集成。与 M1 不相关的工具可以预研，但不得使用尚未冻结的中心新 API 编码后自称可集成。

这道门的目标是防止过去「单模块先 merge，大量 DORMANT，随后才发现 Host public seam 不匹配」的失误。

## 4. M2：并行工具改造 + 持续接线，不再集中总装

### 4.1 建议 Lane 与文件所有权

实际 Lane 数量与同名工具归属由 M0 全量矩阵确定。初始建议如下，**目录只是现有实现的技术定位，不是无条件改动授权**：

| Lane / Owner | 主要拥有的代码 | 必须交付 |
| --- | --- | --- |
| **I：中心唯一装配 Owner** | `agent-bindings.mjs`、`team-tool-plane.mjs`、Host 插件安装入口、Placement / 统一分发/审计装配、公共 Registry / 构建装面清单 | 冻结接口、接线 PR、同 SHA Host C2；与各 Lane 做受控集成 |
| **A：FS Adapter** | FS Adapter 与相应工具 parser/renderer；受限文件系统核心若需要修正，单独指定 Provider Owner | read/read_image/write/edit/str_replace_editor 全子命令和正负控 |
| **B：Search/Shell Adapter** | `packages/tools/a5p5-tools/`、`search-backend.mjs` / `glob-backend.mjs` / `cancel-leg.mjs`；Shell 由单独子 Owner 或该 Lane 领有 | grep/glob/bash/pwsh 的参数、输出、取消、Spill、原生 parity |
| **P：Provider Infrastructure** | `packages/runtime/controlled-fs/`、`sandbox-provider/`；特别是 Landlock launcher、FD 与进程信号接口 | 公共可靠能力宣称；不在工具代码中另起 Provider |
| **C：Long-lived / Composite** | PTC 外层桥、LSP assembly、per-member 服务池；各有独立不重叠文件 owner | run_code/PTC 内外权限链及真实 LSP 生命周期 |
| **D：External / Jobs / MCP** | `packages/runtime/jobs-gateway/`、Web/MCP/Remote 适配器、Domain Provider 入口；必要时再按文件拆两个子 Lane | 可信远端 Gate、动态注册、跨 Member owner、Job 管理语义 |
| **V：独立验证 Owner** | 验收测试与独立复审；不修改对应 Lane 产品文件 | 冻结 C1/C2 复现、CI 结果归因；C3 统一验收 |

**硬约束**：任一具体共享源码文件只有一个 Writer；尤其 `agent-bindings.mjs`、`team-tool-plane.mjs`、`host.ts`、`scripts/place-dist-glue.mjs`、宿主 pin、全局 Vitest/CI、`packages/testkit/` 的 p4t6 基线都只允许中心/集成 Owner 写。Provider 共用文件只由 P 写。任何工具 Lane 不能「为自己通过测试」直接改中心入口或 CI baseline；提出集成请求和所需 delta 即可。开始前列出实际 path manifest，若有交叉所有权先分配再编码。

### 4.2 每个工具的持续集成协议

1. Lane 从同一冻结的 Contract Tag/基线切独立 branch/worktree，提交 Adapter、C1 contract tests、原生 parity 差异和真正缺口。
2. **C1 GREEN 是给中心集成的请求，不是完成状态**；中心 Owner 立刻在独立集成分支接线，进行 install-dist/Host C2、权限正负控和生命周期检查。
3. 工具代码与其中心接线应视作**一份不可分割的交付单元**：优先一个集成 PR 汇合两个 Owner 的已审核提交；若技术上需要 stacked PR，按 `Adapter → glue` 同一固定窗口顺序合入，不把裸 Adapter 合并成果宣称 DONE，不让未接线代码在 master 滞留并持续发展。
4. 一项完成就汇入当前集成主线，后续 Lane 基于新的集成 HEAD 验证，不能等所有工具都完成后再做一次总接线。
5. 每个交付单元记录其 `codeSha / contractVersion / source+dist / placed definition / native fallback NEG / permission allow-deny-ask / provider effect / cancel+restart / supported profiles`，由独立验证 Owner 按机器可重放证据签名。
6. 中心与工具的契约冲突必须走 §1.3 的变更单，而非执行体自行改设计或跳过原审查失败。

### 4.3 特殊接缝阻断不能悄悄变成延期

对于 PTC 根服务不可替换、LSP policy-generation 输入不可达、动态 MCP 的原生身份丢失、远端 Provider 缺少可信权限原语等，记录：

`Host Pin + 公开 seam + 具体调用形状 + 实测复现 + 缺失的保证 + 最小替代路线（Adapter/R2/R3/有界 Tool Fork/上游请求）+ 安全退路 + 被阻断的必交工具/能力`。

若工具在必交集合内，标为 `BLOCKED-RELEASE` 并交用户做**一次**明确决策（选路线或同意延期/变更需求）；禁止自动把它移动到下一 Alpha 阶段、只保留 Guard 拒绝，或重复生成同类 PoC。技术阻断可并行处理其他不依赖工具，但不允许宣称 Alpha.5 已完成。

## 5. C1/C2/C3：冻结验收并抑制无限返工

| 门 | 验证对象 | 必须有的证据 | 失败时 |
| --- | --- | --- | --- |
| **C1 Adapter** | 单工具接口、参数、Effect、原生等价、Provider 调用与安全负控 | contract suite + pin 原生 parity + 精确错误/result 形 + 取消/超时单元腿 | 工具 Owner 修复；不可凭 mock-only 宣告集成 |
| **C2 Host-integrated** | 真实 Team Agent 的已安装构建和公共分发接缝 | 真实 register→bind→admit/ask→Provider effect→present→dispose；泄漏/原体回落负控 + SHA + Host/port/world + 清理记录 | 中心 Owner+工具 Owner 协作；原体回落、授权绕过均 P0 |
| **C3 Final full-surface** | 固定同一 HEAD、全工具矩阵及跨工具相互影响 | 所有必交工具 C1/C2 证据可重放；跨 Member/Role、注册动态性、取消、冷恢复、并发、工具间命名/权限穿透、构建/安装一致性；独立安全审查 | 不发布；分类阻断并给出收敛决策 |

测试口径先于开发冻结。接受新增真正的安全反例，但提议者必须同时附上：违反的冻结不变量、目标产品代码路径、稳定复现、必须新增的最少断言及成本；纯粹理论可能性、对工装的重复怀疑、历史日志措辞清洗不得无限扩大 C1–C3。关键安全门（未知/回落、绕权、Ask 前副作用、Provider 越界、Definition 漂移、作用域泄漏）**禁止 baseline 豁免**；非关键既有红可以在独立失败身份账中保留，不得笼统报「全套绿」。

**复审上限**：一个独立交付单元默认「首次独立评审 → 一轮针对性修复 → 复审」。如果仍有 blocking finding，**停止该单元的自动重试**，生成一页差异/根因/接口裁决单由中心 Owner 或用户明确下一步；不得自动开新一批候选 PR 重复循环。兼容 `ROUTER_RULES` 的最多三轮 review 上限，**不是**两轮后忽略安全失败。修复测试缺陷时应保留原红记录，明确「测试错误」与「产品缺陷」归因；工装修复不得偷降断言。

## 6. M3：只存在一次 Alpha.5 完整验收

在所有必交工具的 C2 结束后，冻结候选产品 HEAD，不以漂移中的 master 或早期候选的历史绿账替代：

- **覆盖封闭**：Dot 的完整工具矩阵每行明确归属、接管方式、可达路径、正向能力、预期拒绝的限制、C1/C2 证据与最终 C3 状态；必须达到实际 dispatchable 入口 **100% 有安全归宿**，且必交工具全部 FUNCTIONAL；不得把未交付主体藏在 `UNSUPPORTED` 标签里。
- **审批与安全**：all/ask/deny，读/写/网络能力和实际 Provider 强制，Grant once、撤销后不可重放、动态注册/撤销、PTC 内层、MCP、Jobs 跨 Member、LSP 世代与冷恢复；所有未治理 Body/原体回落负控必须绝对通过。
- **运行语义**：真实业务正控、结果展示/Spill、大小上限、子进程退出/取消与终止不确定状态；每工具正向与拒绝路径真实存在。
- **工件闭环**：提交源码/构建 dist/pnpm pack/安装 manifest/launcher ABI 版本和 checksum/工具实际注册表一致；不允许只通过源码 unit tests。
- **独立验收**：由未编写对应实现的 reviewer 在固定 Host/固定 SHA 上复验关键安全负控与至少跨工具组合；如环境不足，必须列为 BLOCKED，不得把 NOT_RUN 记成 PASS。
- **唯一终判**：只有以上全部满足，并经用户按仓库既有流程确认，才允许更新 Alpha.5 的阶段完成声明；不存在独立「试用版完成」的出口。

## 8. PR、分支、审查与证据纪律

1. **本计划 PR 只新增本文件**，不修改现有源码/测试/状态与 Dot 管辖的文档。经用户审阅并合并后，由 Dot 依据当前代码/计划事实更新 `AGENTS.md`、阶段指针、`docs/STATUS.md`，并在唯一真值目录链接本计划；本 PR 不自动授权实施与合并后续工具代码。
2. M0 和 M1 各由具名主 Owner 提交目标明确的 PR；M2 各 Lane 只有一个活跃 implementation PR / integration unit。避免并行堆积多轮「证据 PR」「接线 PR」「修复 PR」但无人能声明最终完成。
3. 1 task = 1 branch = 1 worktree = 1 writer；所有修订必须正向提交，不 force-push 已审历史、不直推 `master`。如果一个短时协调记录无需产品变更，优先附在对应 PR，而非自动开新 PR。
4. 中心 Owner 独占 Host/setup/glue/build 共享文件；各工具 Agent 独占各自已注册路径。真正要求改共享文件时提交 interface delta 给中心，禁止多 Writer 冲突和后置大规模集中接线。
5. 评审必须同时验证接口语义、真实副作用与测试可信性；安全 Reviewer 不参与被审代码实现。对于同一固定 HEAD，记录既有红身份、代码新增红、NOT_RUN、每个配置保证维度，绝不把未执行门计入绿。
6. 每次工具交付产生简短的机器可读收据，至少含：`tool/family, hostPin, contractVersion, sourceSha, builtArtifactHash, placedBindingIdentity, realHostOutcome, negativeControls, supportedProfiles, remainingBlockers, reviewer`。
7. 任何为了达到 Alpha.5 最终目标而提出的“临时试用阶段”“先支持一部分工具再扩展”等范围收缩，都不在本计划授权内；必须重新请用户裁决。
