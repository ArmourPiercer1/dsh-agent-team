# 0.1.1-alpha.2 详细开发计划

> 版本定位：
>
> **0.1.1-alpha.2 = Static Parameter-Aware Permission + Synchronous Approval**
>
> alpha.2 的唯一目标，是在 alpha.1 capability wiring 之上，引入“针对具体工具参数/资源的静态权限判断”，并在 `ask` 情况下复用现有 Control plane 完成同步的 `allow once / deny`。
>
> 本文档可直接作为本地 agent 的执行计划。禁止扩大成完整动态权限治理版本。

---

# 1. Release Goal

最终 Blueprint Template 能表达类似：

```yaml
capabilities:
  teamTools:
    kind: allow
    items:
      - team_delegate
      - team_send_message

  builtinToolDeny: []

  skills:
    kind: deny

  mcp:
    kind: deny

  permissions:
    default: ask

    allow:
      - tool: read
        resource:
          kind: exact
          path: ./README.md

    ask:
      - tool: write
        resource:
          kind: exact
          path: ./output/result.json

    deny:
      - tool: edit
        resource:
          kind: exact
          path: ./src/critical.ts
```

运行路径：

```text
具体 tool call
    ↓
CanonicalOperation
    ↓
Static Permission Resolver
    ├ allow → execute
    ├ deny  → block
    └ ask
         ↓
      ControlRequest
         ↓
      Leader / Human decision
         ↓
      exact allow-once consumption
         ↓
      execute exactly once
```

# 3. 架构边界

必须保持两类概念分离：

```text
Capability selection
=
这个 Agent 有哪些 tool / skill / MCP

Operation permission
=
某个具体 tool call 在这个参数/资源下是否允许
```

因此 alpha.1 的：

```text
teamTools
builtinToolDeny
skills
mcp
```

继续由 capability wiring 管理。

新的：

```text
permissions
```

只在：

```text
tools/pre-execute
```

阶段生效。

不要把新的 path/argument permission 直接塞入现有 generic `TemplatePolicy.values['permissions']`，也不要让 generic policy resolver 承担 path matcher。

推荐新模块：

```text
packages/domain/permission/
packages/runtime/operation-permission/
```

# 4. 支持工具范围

alpha.2 第一版优先支持 primary resource 清晰的 file tools：

```text
read
read_image
write
edit
lsp
```

其中都以目标文件作为 primary resource。

对于 Bash / shell：

```text
只允许 tool-level ask / deny
不提供 positive parameter-level allow
```

因为单个 command 字符串不能可靠表达真实资源/effect。

如需要最小 shell 权限，只允许：

```yaml
- tool: bash
  resource:
    kind: any
```

含义是整个工具进入 ask/deny；不允许命令 regex、前缀 allow、路径推断等。

# 6. A1 — Permission Schema

## 6.1 目标

在 Template capabilities 中新增 optional：

```ts
permissions?: TemplatePermissionPolicy
```

建议：

```ts
interface TemplatePermissionPolicy {
  default: 'ask' | 'deny'
  allow: readonly PermissionRule[]
  ask: readonly PermissionRule[]
  deny: readonly PermissionRule[]
}
```

alpha.1 Blueprint 未声明 `permissions` 时：

```text
完全保持 alpha.1 behavior
不安装 parameter permission listener
```

## 6.2 PermissionRule

最小规则：

```ts
type PermissionTool =
  | 'read'
  | 'read_image'
  | 'write'
  | 'edit'
  | 'lsp'
  | 'bash'

interface PermissionRule {
  tool: PermissionTool
  resource:
    | { kind: 'exact'; path: string }
    | { kind: 'any' }
}
```

若 public filesystem seam 已可靠支持 descendant relation，可加入：

```ts
| { kind: 'subtree'; path: string }
```

但 `subtree` 不是 release blocker；若无法通过 public seam 严格判断，就延后。

## 6.3 Schema 约束

必须：

```text
default required when permissions present
default ∈ ask|deny
allow/ask/deny required arrays
unknown fields reject
unsupported tool reject
resource.kind closed vocabulary
exact.path non-empty
any 不得携带 path
duplicate rules 允许但规范化必须 deterministic
```

禁止 `default: allow`，避免 silent privilege expansion。

## 6.4 同层优先级

冻结为：

```text
deny > ask > allow > default
```

## 6.5 A1 Tests

至少：

```text
legacy Blueprint parses
permissions omitted works
default ask parses
default deny parses
default allow rejects
unknown field rejects
unknown tool rejects
exact without path rejects
any with path rejects
hash changes when permissions change
duplicate normalization deterministic
```

# 7. A2 — Canonical Operation

这是 alpha.2 的核心安全边界。

## 7.1 新模块

建议：

```text
packages/runtime/operation-permission/canonical-operation.ts
```

输出：

```ts
interface CanonicalOperation {
  tool: PermissionTool

  resource: {
    kind: 'file' | 'tool'
    key: string
    display: string
  }

  fingerprint: string
}
```

语义：

```text
resource.key     = authority identity
resource.display = UI/debug only
fingerprint      = exact operation impact identity
```

## 7.2 原则

禁止直接用原始 path string 做 authority identity。

必须：

```text
upstream public filesystem canonicalization / resolution seam
→ canonical resource identity
```

如果 upstream 返回 opaque key：

```text
把它当 opaque
不要自行 parse
```

## 7.3 Primary Security Parameter

每个 tool 只定义一个 primary resource。

### read

资源：文件。

fingerprint projection：

```json
{
  "tool": "read",
  "resourceKey": "...",
  "offset": 0,
  "limit": 100
}
```

### read_image

```json
{
  "tool": "read_image",
  "resourceKey": "..."
}
```

### write

```json
{
  "tool": "write",
  "resourceKey": "...",
  "contentHash": "sha256:..."
}
```

不要持久化完整 content。

### edit

```json
{
  "tool": "edit",
  "resourceKey": "...",
  "oldHash": "sha256:...",
  "newHash": "sha256:...",
  "replaceAll": false
}
```

### lsp

资源仍是目标文件；fingerprint 只保留改变该 LSP 操作语义的字段，例如 operation/line/character。

## 7.4 Fingerprint

统一：

```text
fingerprint = sha256(canonicalJson(securityProjection))
```

要求：

```text
deterministic
覆盖所有 security-relevant fields
无 timestamp
无 random id
无 display string
```

## 7.5 Fail-closed

若 template 开启 permissions，而受支持 tool 的 canonical resource 无法解析：

```text
deny
```

不能：

```text
canonicalization failed → next()
```

对于完全 unsupported tool：不进入 parameter resolver；Bash 若存在 `resource:any` rule 则走 tool-level rule。

## 7.6 A2 Tests

至少：

```text
same path spellings → same resource key
different file → different key
write same file same content → same fingerprint
write same file different content → different fingerprint
edit old/new change → fingerprint changes
read offset/limit change → fingerprint changes
display changes不影响 authority
malformed path → fail closed
```

Windows 重点：

```text
separator normalization
case semantics 按 upstream contract
relative vs absolute
.. traversal
symlink/junction 若 public seam 可表达
```

不要自行定义 Windows path semantics。

# 8. A3 — Static Operation Permission Resolver

## 8.1 接口

```ts
resolveOperationPermission(
  policy,
  operation,
  canonicalRules,
): PermissionDecision
```

输出建议：

```ts
type PermissionDecision = {
  decision: 'allow' | 'ask' | 'deny'
  provenance: {
    source: 'rule' | 'default'
    effect: 'allow' | 'ask' | 'deny'
    lane?: 'allow' | 'ask' | 'deny'
    ruleIndex?: number
  }
}
```

## 8.2 Matcher

alpha.2：

```text
exact:
  canonical rule key === operation resource key

any:
  tool match 即可
```

如实现 subtree：必须使用 canonical filesystem seam；禁止 `startsWith(path)`。

## 8.3 Resolution

```text
collect all matching rules

if any deny → deny
else if any ask → ask
else if any allow → allow
else → policy.default
```

## 8.4 A3 Tests

```text
allow exact
ask exact
deny exact
any allow/ask/deny
deny > ask > allow
no match + default ask
no match + default deny
same raw spelling / same canonical resource
different canonical resource
```

# 9. A4 — Control Exact Scope + Synchronous Wait Bridge

alpha.2 必须复用现有：

```text
ControlRequest
ControlDecision
guardOperation
exactly-once consumption
Leader/Human resolver roles
durable rows
```

不要重建审批后端。

## 9.1 扩展 ControlOperationScope

增加 optional：

```ts
readonly operationFingerprint?: string
```

保持 optional，兼容旧 Control rows。

同步修改：

```text
parseScope
request payload
decision payload
consumption payload
scope snapshot
scope key
request idempotency key
scopeSnapshotMatches
tests
projection / Remote DTO（若 scope 被公开展示）
```

## 9.2 兼容语义

```text
old Team control operation:
  operationFingerprint absent
  → old behavior

new parameter permission:
  operationFingerprint present
  → approval bound to exact fingerprint
```

## 9.3 correlation 与 fingerprint

严格分开：

```text
correlation
=
逻辑 invocation id
推荐当前 tool callId

operationFingerprint
=
resource + payload impact identity
```

不能用 fingerprint 替代 correlation，否则相同 write 内容未来无法发起新的独立审批。

## 9.4 Synchronous wait bridge

新增最小接口：

```ts
awaitControlDecision({
  rootSessionId,
  requestId,
  signal,
}): Promise<ControlDecisionRecord>
```

authority 永远是 durable Control rows；waiter 只解决 liveness。

### 最小实现

alpha.2 推荐使用 polling：

```text
250–500 ms
```

轮询 control state，直到：

```text
decision appears
signal aborted
Agent closes
Host shuts down
```

不要为 alpha.2 建 durable waiter scheduler 或跨进程 continuation。

## 9.5 Routing

Member ask：

```text
leader-approval
```

Leader ask：

```text
user-approval
```

复用现有 resolver role：

```text
leader-approval → leader | human
user-approval   → human
```

## 9.6 UI/Remote

不升级 decision vocabulary；现有：

```text
allow
deny
```

即可。

产品语义：

```text
allow = allow once
```

如成本极低，可把 UI 文案改成 `Allow once`；禁止增加 always allow / grant instance。

## 9.7 A4 Tests

```text
C1 fingerprint participates in exact scope
C2 old scope without fingerprint remains compatible
C3 same correlation + different fingerprint 不可错误复用
C4 allow → first guard consumes → second guard allow-consumed
C5 pending/decision/consumption survive fresh ControlService instance
```

# 10. A5 — tools/pre-execute Enforcement

## 10.1 Agent-scoped listener

仅对声明了 `permissions` 的 Agent scope 安装：

```text
tools/pre-execute
```

只处理 alpha.2 支持的 permission tools。

## 10.2 Pipeline

固定：

```text
tools/pre-execute(exec)
    ↓
is supported permission tool?
    ├ NO → next()
    └ YES
        ↓
canonicalize(exec.arguments)
        ↓
resolve static permission
        ├ allow → next()
        ├ deny  → return deny
        └ ask
            ↓
        requestControl()
            ↓
        awaitControlDecision()
            ↓
        decision deny → return deny
        decision allow
            ↓
        guardOperation(exact scope + fingerprint)
            ↓
        allowed → next()
        blocked → deny
```

## 10.3 Zero-effect invariant

以下所有情况必须满足：

```text
tool execute() ZERO calls
```

包括：

```text
static deny
pending
resolved deny
scope mismatch
allow consumed
wait aborted
canonicalization failure
external hard denial
```

## 10.4 Cancellation

若 Agent turn canceled、Host close、tool signal aborted：

```text
waiter must settle
no leaked promise
no later accidental execution
```

## 10.5 External hard

不要在 listener 中建立第二套 hard policy。

优先复用现有 ControlService decision-time external hard check，并确认 last-mile 是否已有 fresh hard check。

若 current ControlService 无法满足“批准后、执行前 externalHard 再确认”的安全要求，将其记录为 alpha.2 security blocker，做最小补丁；不要顺手引入 `teamHardDeny`。

# 11. A6 — Production Wiring

## 11.1 Hotspot ownership

唯一 integration writer：

```text
packages/runtime/src/plugin/root.ts
packages/runtime/src/plugin/live/agent-bindings.mjs
```

禁止多个 implementation agent 并行修改这两个文件。

## 11.2 Agent lifecycle

每次：

```text
fresh root
fresh member
cold root
cold member
```

重新：

```text
resolve durable identity
→ bound BlueprintTemplate
→ static permission policy
```

如果 `permissions` absent：

```text
不安装 permission listener
```

这样 legacy/alpha.1 behavior 完全不变。

## 11.3 Listener lifecycle

pre-execute listener 必须：

```text
Agent scoped
lifecycle owned
close/dispose 时解除
cold resume 时重新安装
```

不得使用 module-level mutable authority。

## 11.4 No dynamic mutation

alpha.2 permission policy 是每个 Agent lifecycle 从 bound template 重建的静态策略。

不需要：

```text
runtime context injection
permission CAS
hot mutation
snapshot coordinator
```

# 12. V1 — Verification Matrix

## 12.1 Static decisions

准备：

```text
file A: allow read
file B: deny read
file C: ask write
file D: no match / default ask
file E: no match / default deny
```

验证：

```text
A executes
B zero execution
C creates request
D creates request
E zero execution
```

## 12.2 Exact allow-once

调用：

```text
Write(fileC, "payload-1")
```

批准后：

```text
first invocation → executes once
same request second consume → allow-consumed → zero second execution
```

新 invocation：

```text
same file + same payload + new callId → new request
same file + different payload → old approval unusable
other file → old approval unusable
```

## 12.3 Routing

Member：

```text
ask → leader-approval
Leader can allow/deny
Member cannot self-resolve
```

Leader：

```text
ask → user-approval
Leader cannot self-resolve
Human can resolve
```

## 12.4 Cold resume

alpha.2 不要求正在等待的 JS promise 跨进程恢复。

只要求：

```text
static permission policy rebuilt correctly
pending durable ControlRequest still visible
existing decision preserved
existing consumption preserved
```

进程死亡时同步等待中的 tool call 终止，是 alpha.2 可接受行为。

## 12.5 Regression

继续验证 alpha.1：

```text

MCP
legacy Blueprint
cold resume

```

## 12.6 Safety negatives

至少：

```text

Leader self-approval on user-approval forbidden
```

# 19. 最终实现原则

alpha.2 只回答一个问题：

> **“某个具体工具，在某个具体资源和参数下，是否可以执行？”**

最终 authority chain 必须保持：

```text
Template static permission
        ↓
CanonicalOperation
        ↓
allow / ask / deny
        ↓
ask only:
existing durable Control
        ↓
exact fingerprint
        ↓
allow once
```

任何超出这条链的能力，都不属于 alpha.2。
