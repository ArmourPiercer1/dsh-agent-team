   SAFE only after a guard that does not exist today:
     (a) a `build_root` field inside hostCacheKey (hashed into `key`), and/or
     (b) an explicit assertion in the verify step that the recorded build root equals the directory
         being restored to,
   plus the existing HEAD-pin / entry-point / porcelain assertions and a boot. Restore to the same
   absolute path (/home/runner/work/<repo>/<repo>/tests/deepseek-harness-test-use) and the bytes
   verify either way; the guard is what makes a DIFFERENT path fail loudly instead of passing.
   Restoring 2.3 GB took 21.3 s locally (rsync -a), which bounds the restore side of the 216 s.

   WHAT A GREEN VERIFICATION DOES NOT PROVE:
     - not that the artifact was BUILT FROM the recorded commit (the manifest is unsigned);
     - not that it came from THIS path (measured in 4);
     - not that the embedded absolute paths in the 49 client bundles resolve to the serving tree;
     - not that it is RUNNABLE (boot is a separate exercise, and boot does not read those bundles).
