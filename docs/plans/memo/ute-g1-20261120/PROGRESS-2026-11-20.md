# UTE-3 progress board — 2026-11-20 (dated snapshot, append-only; the ledger is the authority)

**What this file is.** A dated snapshot of the per-family migration/retirement
matrix, written so that a reader can see the whole board in one place without
re-deriving it from nine ledgers. It is **not** an authority: the machine
authority is `dev/agent-workflow/ledgers/ute-retirement.json` graded by
`scripts/ute-retirement-gate.mjs`, and the derived readiness shown here is
computed by that gate, never asserted by hand.

**How every cell is graded.** `RetireAllowed = OldBaseline ∧ NewPathVerified ∧
SemanticDifferencesResolved ∧ NegativeControlsPass` (`RETIREMENT.md` §1). A
family may retire **incrementally** and only on its own evidence; a green FS cell
is not evidence for Search, and a green Search cell is not evidence for Web
(`RETIREMENT.md` §2). `UNKNOWN`, an unobserved effect, or a skipped arm is never
a PASS.

## 2. What the FS family proves about the method (and what it does not)

**Proves.** The four-tool assembly is one indivisible retirement unit
(`unit=4/4`; a partial claim is `UTE_UNIT_UNDERCLAIMED`). Old path reproduces
byte-identically twice. The new path reproduces all 16 vectors with an effect
oracle that digests bytes **read back from the committed attachment store**, not
a caller buffer or a self-report, and refuses 0 or >1 attachments. Every refusal
lands in a closed category vocabulary with a TOTAL mapping in both directions,
and an unmapped value is `REFUSAL_VOCABULARY_INCOMPLETE` rather than a default
bucket. Thirteen negative controls, one per member, each with a positive arm.

**Does not prove.** Read confinement is `CLAIM_NOT_OBSERVABLE` — a refusal record
pins the refusal, the absent secret and an unchanged tree; it cannot prove no
unauthorized read happened. The image rows are covered on the prototype lane,
not by the product module (`packages/tools/src/native-fs-binding.ts` still
claims read/write/edit, ten vectors). No live boot on the new path. And the two
semantic differences remain real: a lane denial surfaces as
`FS_PERMISSION_DENIED` on the new path versus `FS_SANDBOX_DENIED` on the old,
and the observation shape is a typed `FsError` versus prose.

## 3. Where the owner's signature is required (not delegated)

1. **FS `SemanticDifferencesResolved`** — a reference-bound record
   (`PR #<n> @ <40-hex>` resolvable to a HEAD ancestor) for the two blocking
   differences. The route-B+C ruling of 2026-11-20 (native structured `FsError`
   kept; compatibility judged by the closed refusal-category mapping) is
   recorded as a **technical route only** and is explicitly **not** that
   signature.
2. **The Search differences** — including `SD-SEARCH-1`, which is not a framing
   difference but a behaviour defect on the product route: a path-less `grep`
   returns zero matches because the host module omits the path operand and the
   child's stdin is a readable socket. It is recorded, not fixed; fixing it is a
   product change with its own baseline movement.
3. **Whether a baseline captured under an as-yet-unmerged repair is acceptable**
   (FS's 16-vector re-baseline followed the route-C `read_image` repair, PR
   #802). The ledger records the capture point; the acceptability is a ruling.

## 4. Deliberately not done

No production execution-path switch, no legacy ToolPlane/Family Body deletion,
no Authority migration, no upstream modification, no approval record, and no
weakening of any assertion to make a cell green. The consolidation verbs are the
owner's; this board exists to make the request reviewable.
