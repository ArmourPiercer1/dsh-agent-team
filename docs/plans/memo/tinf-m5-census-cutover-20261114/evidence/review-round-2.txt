## 4. Finding-by-finding

1. **Suite not hermetic** — fixed (tmpdir fixtures, injectable output dirs); before/after in §1.
2. **Latent false RED** — `rootsFromReport` now counts exactly `status === 'failed'` (legacy
   `scripts/fail-set.mjs` semantics), counts `skipped`/`pending`/`todo` separately, and prints
   `skipped=` plus `assertions=` on the capture line. An UNKNOWN status is a FAIL
   (`UNKNOWN_ASSERTION_STATUS`) — stricter than legacy, never looser. Tests: "a skip is NOT a
   failure (legacy semantics)…", "an unknown assertion status is a FAIL…".
3. **Evidence trusted, not verified** — `verifyEvidenceRefs()` resolves each reference against the
   shard's own directory and requires an existing, non-escaping file whose evidence artifact lists
   the fragment's root (`RESULT_EVIDENCE_OUTSIDE` / `RESULT_EVIDENCE_UNREADABLE` /
   `RESULT_EVIDENCE_UNKNOWN_ROOT`); it runs on the GRADED BYTES in the aggregator CLI and in
   `aggregateArtifacts`. The runner writes `census-evidence-<capture>.json` beside the shards and
   re-anchors every result to it. A replay now must carry `merge_tree` == the plan's
   (`DRYRUN_IDENTITY_MISMATCH`) and cover every planned root (`DRYRUN_COVERAGE_MISMATCH`). Evidence
   files relabelled (§3): the replay is SYNTHESIZED; no real recording exists.
4. **Dead guard** — the identity is always the checkout's `gitTreeSha`; `EB3_MERGE_TREE` is a CLAIM
   compared in two independent places (claim vs checkout, claim vs the plan's recorded identity).
   Test: "EB3_MERGE_TREE naming another tree refuses PLAN_MERGE_TREE_MISMATCH".
5. **Stale report reuse** — plan reports are written to `census-<stamp>-<pid>-<capture>.json` and
   unlinked before the spawn; a crash leaves no report, so the leg refuses `CENSUS_REPORT_MISSING`
   instead of grading the previous bytes. The plan argv is otherwise untouched (only
   `--outputFile.json=` is rewritten). Test: "a stale report at the graded path is UNLINKED…".
6. **Build stamp staleness** — the current surface is re-hashed on every recorded stamp:
   `BUILD_STAMP_STALE` on any byte/count/path difference, `BUILD_STAMP_UNVERIFIABLE` when the
   surface cannot be hashed at all (refused, never trusted). Tests: "a same-tree stamp whose bytes
   changed is BUILD_STAMP_STALE" (and the unverifiable branch in the same case), plus the CLI's
   `--verify` now re-hashes.
