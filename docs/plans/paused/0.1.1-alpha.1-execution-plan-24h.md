## 3. 冻结最小契约

### FC-1：闭合权限 grammar

```ts
type PermissionDefault = 'ask' | 'deny'
type PermissionDecision = 'allow' | 'ask' | 'deny'
type PermissionTool = 'read'|'read_image'|'write'|'edit'|'lsp'|'bash'
type PathMatcher =
  | { kind: 'exact'; path: string }
  | { kind: 'subtree'; path: string }
  | { kind: 'any' }
type BashMatcher = { kind: 'command-class'; commandClass: 'bash' }
type PathPermissionRule = {
  tool: 'read'|'read_image'|'write'|'edit'|'lsp'
  effect: 'allow'|'ask'|'deny'
  primaryArgument: 'path'
  matcher: PathMatcher
}
type BashPermissionRule = {
  tool: 'bash'
  effect: 'ask'|'deny'
  primaryArgument: 'command'
  matcher: BashMatcher
}
type PermissionRule = PathPermissionRule | BashPermissionRule
type PermissionPolicy = { default: PermissionDefault; rules: readonly PermissionRule[] }
```

This is a discriminated union: path tools cannot carry command fields; Bash cannot carry path fields or `allow`; `any` is a path-matcher variant only and is not duplicated as an outer-rule matcher or Bash matcher. Bash `command-class` is the sole matcher kind for Bash, with the exact fields `{ kind, commandClass }`; it matches the normalized Bash command family only, never a command payload or positive allow. Exact field sets reject unknown keys.

字段闭合、unknown reject；路径工具只允许 `exact/subtree/any`，没有 glob/glob-like string、regex、prefix、shell pattern、boolean expression、opaque DSL。Bash 只允许 `command-class` matcher；`commandClass: 'bash'` 只标识归一化命令族，不授权任意命令，具体 command payload 必须进入 canonical fingerprint。`exact` 匹配一个 canonical resource；`subtree` 匹配 upstream resolver 定义的 canonical descendants；路径 `any` 是声明 operation kind 的全资源匹配。`default` 仅 ask/deny；无 default reject。Bash allow rule reject，只能 ask/deny。层内冲突 `deny > ask > allow`；无 match 使用 default；`teamHardDeny` reject。Windows case/drive/UNC/separator/dot-segment/symlink/descendant 语义全部来自 upstream/public resolver，禁止 raw `startsWith`。

### FC-3：Canonical operation/fingerprint

```ts
interface CanonicalOperation {
  toolName: PermissionTool
  operationClass: 'read'|'write'|'edit'|'lsp'|'shell'
  primaryArgumentKind: 'path'|'command'|'none'
  canonicalResource: string | null
  securityRelevantArguments: Readonly<Record<string,string|number|boolean|null>>
  operationFingerprint: string
}
```

Fingerprint 是独立 scope 字段，不能由 resource 或 correlation 替代：SHA-256(sorted deterministic JSON of **all** security-relevant fields). security vectors 至少如下：

| tool | 必须纳入的 securityRelevantArguments |
|---|---|
| read | canonical path；encoding/range/offset/limit 等改变读取目标或内容的参数 |
| read_image | canonical path；format/frame/page/region 等改变读取对象的参数 |
| write | canonical path；content hash/length、encoding、create/overwrite/mode 等影响写入的参数 |
| edit | canonical path；old/new content hash、edit range/patch mode、encoding 等影响变更的参数 |
| lsp | canonical path；operation/subcommand、position/range、workspace/root、query/format options 等影响访问的参数 |
| bash | normalized command class and complete security-relevant command payload/options; positive parameter allow forbidden |

只可排除已证明 non-security metadata；任何 security-relevant 变化必须改变 fingerprint。canonicalization 缺失/失败 fail closed。

### FC-4：同步 ask/control protocol

```ts
interface StaticControlScope extends ControlOperationScope {
  canonicalResource: string | null
  operationFingerprint: string
}
type StaticControlDecision = 'allow_once' | 'deny'
```

`tools/pre-execute` callback 在工具 dispatch 前必须调用 upstream public `ctx.approval.request(...)`，并 await 其同步返回的 `ApprovalOutcome`；该 awaited API 是 alpha.1 唯一 ask authority，不得用自定义 F9-compatible callback 替代。公开 API 的返回值**只有 `ApprovalOutcome`**，不得声称或依赖其返回 `requestId`、scope 或完整 control request。可实现的 alpha.1 协议是：① pre-execute 在调用前生成内部随机 `requestId`，构造完整 `StaticControlScope`（含 canonical resource 与 operation fingerprint），并在当前 Fiber/调用生命周期内保存 `requestId → StaticControlScope`；② control adapter 用该内部 correlation 创建/登记现有 control request，并把展示 request 与 correlation 关联；③ `ctx.approval.request(...)` 仅返回 `ApprovalOutcome`，adapter 将 outcome 与本地 mapping 及既有 request/decision 映射关联，校验 scope/fingerprint 后提交既有 lock/exact-once consumption；④ 仅 `allowed-once` 映射为 `allow_once` 并放行一次，`rejected`、`cancelled`、`unavailable`、timeout、stale、malformed、missing 均 deny，任何 correlation/scope 缺失或不一致均 fail closed。live ask 还要求**单独验证的 public answerer bridge**：必须能把用户对已登记 control request 的决定通过公开 seam 返回给等待中的 `ctx.approval.request(...)`；F9 durable request/decision 展示本身不是 answerer。P0 必须给出该 bridge 的最小复现与证据；若不存在或无法证明，live ask path 明确 `BLOCKED/DEFERRED`（不是 ambiguous），仅交付无需 live answer 的静态 allow/deny 路径。无 grant/escalation/async continuation/restart-safe new grant。
